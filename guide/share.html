10Sharing and backup

Devices with their passwords, and optionally the app settings (LiveView Mix pages and control panels), can be moved to another device or shared with other people as an encrypted code, or backed up to iCloud as several named backups and restored on one's own iPhone, iPad and Apple TV.

Comparing the two methods

TopicSharing codeiCloud backup
WhereSettings › Export Cameras and Settings › Import Cameras, in the Share Cameras sectionSettings › Back Up to iCloud and Settings › Restore from iCloud, in the Backup & Restore section
iCloud neededNo. The code travels by any means the user chooses.Yes. Both devices must be signed in to iCloud with the same Apple Account.
Choice of devicesThe devices to export can be ticked.All devices.
App settingsOptional; included only when Include app settings is on, and applied only when the recipient agrees.Always included.
Copies keptEach export produces a separate code.My Backup keeps several backups, each with an optional name; the Apple TV destination keeps one copy.
LockNo lock, a six-digit PIN, or a password.No PIN. Encrypted with a key built into the app.
Devices that can use itCam Hub of other people, and one's own iPhone and iPad. Apple TV can only import.One's own iPhone, iPad and Apple TV.
Typical useSharing with other people, or two devices that do not share an Apple Account.Changing phones, keeping earlier states of the setup, or bringing the settings to Apple TV.

Exporting cameras (creating a code)

Prerequisite: at least one device has been added. While there is no device, Export Cameras is unavailable.

  1. Tap the Settings tab at the bottom of the screen.

    Check: The screen shows the settings list.

  2. In the Share Cameras section, tap Export Cameras.

    Check: The Export Cameras page opens: the Devices to export list (all ticked by default), Lock with a PIN, Include app settings, and a button such as Export 5 devices.

  3. Optional: tap a device row to clear or restore its tick.

    Check: The export button shows the number of selected devices, for example Export 3 devices. While every device is ticked, the button at the right of the list title reads Deselect all and clears every tick; while any device is not ticked, it reads Select all and ticks every device. While no device is selected, the export button is unavailable.

  4. Optional: turn on Include app settings.

    Check: The switch is on, and the explanation below it changes to say that the code also carries the app settings, the same as restoring from iCloud. For the items carried, see “What backups and codes contain”.

  5. Optional: set the lock as described in “Locking a code”.

    Check: After a lock has been set, Export 3 devices stays unavailable until the entry is complete. Without a lock, the code is open: anyone who has the code and Cam Hub can import it.

  6. Tap the export button, for example Export 3 devices.

    Check: The result page opens with the title Export Cameras. Its top part explains that the code contains the cameras and their passwords, encrypted. For an open code it adds, with an orange mark, that anyone with the code and Cam Hub can add them; for a locked code it reminds that the PIN or password must be sent separately. Below are the buttons Share and Copy, and below those the full text of the code.

  7. Tap Share and select a way to send, or tap Copy.

    Check: Tapping Share opens the system share sheet, with options such as Messages, Mail or AirDrop. Tapping Copy changes the button to Copied, and the complete text of the code is on the clipboard.

  8. Tap Done in the top-right corner.

    Check: The result page closes and the Export Cameras page is shown again.

  • Share sends a link, Copy copies text. Share sends a link that begins with https://cam-hub.almx.cc/i#, with the code after the “#”, which browsers do not send to the web server. Copy places the complete text on the clipboard.
  • The recipient: when Cam Hub is installed, opening the link opens the import page directly with the code filled in. When it is not installed, the link opens a web page that points to the download page of the app and shows the code for copying.
  • The text of the code begins with a short English explanation and the install address, followed by the code, which begins with CAMHUB1:, CAMHUB1L: or CAMHUB2: and can be thousands of characters long. When importing, the whole text can be pasted, or the code alone.
  • A code contains the passwords of the devices. A code does not expire, and deleting the devices or the app on the source device does not invalidate a code that has already been shared. When a code may have been exposed, change the passwords of the devices concerned.
A code hands over the passwords of the devices

Anyone who obtains a code without a lock and has Cam Hub can import every device in it with its password. Send the code only to people who are trusted, and set a lock when needed.

Locking a code

A code can be open, locked with a six-digit PIN, or locked with a password (Complex encryption). The strength of the protection differs greatly between the three, and the choice depends on how the code is sent.

Locking with a six-digit PIN

  1. On the Export Cameras page, turn on Lock with a PIN.

    Check: The field PIN (6 digits) appears below the switch, and the explanation changes to say that whoever imports must enter this PIN and that it must be sent separately from the code.

  2. Enter six digits.

    Check: The field accepts digits only, the keypad closes after the sixth digit, and the export button becomes available. With fewer digits, the export button stays unavailable.

Locking with a password (complex encryption)

  1. On the Export Cameras page, turn on Lock with a PIN.

    Check: The Complex encryption switch and the PIN (6 digits) field appear.

  2. Turn on Complex encryption.

    Check: The PIN field is replaced by the two fields Password (8+ characters) and Confirm password, and anything typed earlier is cleared.

  3. Enter the password in the Password (8+ characters) field.

    Check: The field masks the characters with dots. Any letters, numbers and symbols can be used, and a longer password is stronger.

  4. Enter the same password again in the Confirm password field.

    Check: When both entries match and have at least 8 characters, the export button becomes available. When they differ, the orange text The two passwords don't match. appears below the field and the button stays unavailable.

  • Send the PIN or the password separately from the code, never in the same message.
  • A forgotten PIN or password cannot be recovered. Cam Hub does not store it and does not send it to the developer. When it is forgotten, export a new code.
  • A password is case-sensitive, and spaces count. The same accented letter typed on different keyboards is treated as identical.
  • When a code is placed somewhere that is not private, such as a chat group or an e-mail, lock it with a password and send the password by another channel.
  • The person who imports does not need to know in advance which lock was used. After the code is pasted, Cam Hub recognizes the lock itself and shows the matching prompt and keyboard; see “Importing cameras”.

Importing cameras

Where: Settings › Import Cameras, or directly by tapping a received sharing link.

Pasting a code

  1. Tap the Settings tab at the bottom of the screen.

    Check: The screen shows the settings list.

  2. In the Share Cameras section, tap Import Cameras.

    Check: The Import Cameras page opens. The section title is Paste the code, with the buttons Paste and Import Cameras and a text box.

  3. Tap Paste. Alternatively, touch and hold in the text box and paste manually.

    Check: The code appears in the text box. When the code is locked, a lock note appears below the buttons: Locked with a 6-digit PIN — you'll be asked for it. or Locked with a password — you'll be asked for it. An open code shows no note.

  4. Tap Import Cameras.

    Check: An open code is read at once. When it names another address for a device that is already on this device and does not carry the password of that device, the dialog This code changes camera addresses appears first. Otherwise, a code without app settings is imported directly and the screen shows Added 3 cameras, and a code that carries app settings opens the dialog This code also has the sender's app settings. A locked code opens the Enter PIN dialog (numeric keypad, field 6 digits) or the Enter Password dialog (full keyboard).

  5. For a locked code, enter the PIN or the password and tap Import.

    Check: The dialog closes, and a spinner appears below Import Cameras while the code is unlocked, which can take a moment; Import Cameras is unavailable meanwhile. The import then continues as for an open code: with the dialog This code changes camera addresses, the dialog This code also has the sender's app settings, or Added 3 cameras.

  6. When the dialog This code changes camera addresses appears, tap Use New Addresses or Keep Current Addresses.

    Check: The dialog lists each device concerned on one line, with its current address and the address in the code, and explains that the passwords saved in Cam Hub for these cameras would then go to the new addresses. After either choice, the screen shows Added 3 cameras, or, for a code that carries app settings, the dialog This code also has the sender's app settings. Cancel closes the dialog and imports nothing. For what each choice changes, see “When a code changes camera addresses”.

  7. When the dialog This code also has the sender's app settings appears, tap Add Cameras Only or Also Use Their Settings.

    Check: The dialog explains that the LiveView Mix walls, language and other preferences of the sender would replace those of this device and that this cannot be undone. After either choice the screen shows Added 3 cameras. Add Cameras Only leaves the settings of this device as they are; Also Use Their Settings applies the settings of the code. Cancel closes the dialog and imports nothing.

  8. Tap Done.

    Check: The screen returns to the settings list, and the added devices appear in the Devices tab.

When Paste is tapped, the system can ask whether Cam Hub may paste from another app; allow it. Alternatively, touch and hold in the text box and paste with the edit menu.

Cancel in the Enter PIN or Enter Password dialog closes it without importing. A spinner below Import Cameras also shows while the devices are saved and between two dialogs; Import Cameras is unavailable while it shows.

Importing from a link

  1. On an iPhone or iPad that has Cam Hub, tap the received sharing link.

    Check: Cam Hub opens the Import Cameras page with the code already in the text box. For a locked code, the matching lock note is shown.

  2. Tap Import Cameras and, for a locked code, enter the PIN or the password.

    Check: The screen shows Added 3 cameras, or first one or both of the dialogs described in the steps for pasting a code: This code changes camera addresses, then, for a code that carries app settings, This code also has the sender's app settings.

  3. Answer each dialog that appears, as in the steps for pasting a code.

    Check: The screen shows Added 3 cameras.

Message when importingMeaning and action

Wrong PINThe PIN is not correct. Ask the sender for the six digits, then tap Import Cameras again and re-enter it.

  • Importing merges. A device of the code that matches a device already on this device updates it; the other devices of the code are added, and devices already on this device are not deleted. A device matches when it has the same brand, serial number and username, or, when either of the two has no serial number, the same brand, address, HTTP port and username; a code imported on the device that made it also matches its own devices. A matching device takes the name, the model, serial number and firmware version, and the channels of the code. It takes the username, the password and the SNMP settings of a NAS (see “Disk Health”) only when the code carries them, so a password saved on this device is never replaced by an empty one. When the code carries the password of the device, the device also takes the address, the ports and the stream path of the code, and its HTTPS setting follows the rule in “What backups and codes contain”. When the code carries no password for it, the device keeps its address, ports, stream path and HTTPS setting, unless Use New Addresses is chosen in the dialog This code changes camera addresses; see “When a code changes camera addresses”.
  • The enabled state of channels is checked against the plan of this device. When a plan is held, channels beyond its allowance are imported as Disabled. On the free plan, the enabled state is kept as it is in the code, and channels beyond the free allowance show Not in your plan and a lock until a plan covers them. For the allowances, see Chapter 11, “Plans and limits”.
  • App settings are applied only when the code was exported with Include app settings on and Also Use Their Settings is chosen. They then replace the matching settings on this device, including the LiveView Mix pages and the language. A tile that shows a camera not imported with the code becomes an empty tile, and every other tile keeps its place. With Add Cameras Only, or for a code without app settings, the settings of this device stay unchanged.
  • YouTube and Twitch streams in a code are imported like the other devices and use no plan allowance. Before the first stream of a service plays on this device, the terms of that service are shown for agreement; see “YouTube and Twitch streams”.

When a code changes camera addresses

A sharing code can name another address for a device that is already on this device, for example after the address of the sender's camera has changed. When the code carries the password of that device, the device takes the address of the code without a question. When the code carries no password for it, importing would send the password saved on this device to the address in the code, which can belong to someone else. Cam Hub therefore asks first, with the dialog This code changes camera addresses. The dialog and its choices are the same on iPhone, iPad and Apple TV.

When the dialog appears

  • The dialog appears after the code has been read, after the PIN or the password of a locked code, and before the dialog This code also has the sender's app settings. When no device is listed, it does not appear.
  • A device is listed only when all of these apply: the device of the code matches a device on this device (see “Importing cameras”), the code carries no password for it, and the code names another address, another HTTP port or another RTSP port. The same address written differently, for example in capitals or with spaces before or after it, does not count as another address. When the code has no address for the device, the current address counts as unchanged, so only a port can differ.
  • A code carries the password of every device for which the sender's Cam Hub has a saved password. A device without a saved password on the sender's side (see “A device without a saved password”) travels without one.

What the dialog shows

The dialog has one line for each listed device: its name on this device, its current address and the address in the code, each written as address and HTTP port, for example Front Door: 192.168.1.64:80 → 192.168.1.70:80. When the RTSP port differs, both addresses add it, for example Front Door: 192.168.1.64:80 (RTSP 554) → 192.168.1.64:80 (RTSP 8554). Below the list, the dialog explains that the passwords saved in Cam Hub for these cameras would then go to the new addresses, and that the new addresses should be used only when the sender is trusted. The buttons are Use New Addresses, Keep Current Addresses and Cancel.

Item of a listed deviceUse New AddressesKeep Current Addresses

  • Use New Addresses moves only the devices in the list. Every other matching device that arrives without its password keeps its address, ports, stream path and HTTPS setting. Devices of the code that carry their password, and devices that are new on this device, take the address of the code with either choice.
  • Keep Current Addresses imports the code: new devices are added and matching devices are updated, but none of the listed devices moves.
  • Cancel closes the dialog and imports nothing: no device is added or changed.
  • After Use New Addresses or Keep Current Addresses, a spinner can show for a moment below Import Cameras. Then the dialog This code also has the sender's app settings appears for a code that carries app settings; otherwise the screen shows Added 3 cameras.
  • On Apple TV the dialog appears after Import Cameras in the same way; select a button with the remote. For importing a code on Apple TV, see “Bringing the setup to the Apple TV”.
New addresses receive the saved passwords

Choose Use New Addresses only when the code comes from a trusted sender and every listed address is expected. A code that names an address of someone else's server would otherwise send that server the passwords saved on this device. When in doubt, choose Keep Current Addresses or Cancel.

HTTPS after a restore or an import: a backup or a code can turn HTTPS on for a device, with its HTTPS port and trusted certificate, but never turns it off. It does so only when it holds HTTPS for the device with both the port and the certificate; a backup or a code made with an older version of Cam Hub leaves HTTPS as it is. A device that already uses HTTPS on this device keeps its own HTTPS port and trusted certificate, unless the backup or the code moves it to another address or HTTP port and carries HTTPS for it. For a device that arrives in a code without its password, see “When a code changes camera addresses”. To turn HTTPS off, or to trust a renewed certificate, use the HTTPS screen of the device; see “HTTPS for a saved device”. A device that arrives in a backup or a code without a password keeps the password saved on this device.

The app settings comprise: the language; LiveView Mix, that is the landscape page, the portrait page with the Portrait page switch, and the two canvases of iPhone Duo with the Two canvases switch, each with its layout, tile pictures and control panels (with the values of their headers); the arrangement of the preview on the LiveView Mix tab; the option Keep cameras connected between pages; the choice in Open on launch; the device of the Live tab and the Layout of the Full Screen Wall; Default quality, Black bars, Edge-to-edge video and Hide offline cameras; the sound preference; and the range of the network scan. For the LiveView Mix pages, see “The portrait page”.

On a device other than iPhone Duo, the lower canvas and the Two canvases switch are kept but not used; they take effect again when the settings reach an iPhone Duo. Apple TV shows only the landscape page.

Not included: the plan and subscription state (it follows the Apple Account and is retrieved with Restore Purchases; see “Subscribing, restoring purchases and redeeming a code”), saved device reports, the agreement to the terms of YouTube or Twitch (each device asks for it once), and anything not listed above.

Backing up to iCloud

Prerequisite: this device is signed in to iCloud in the system settings. Without a sign-in, the backup stays on this device and does not reach other devices.

  1. Tap the Settings tab at the bottom of the screen.

    Check: The screen shows the settings list.

  2. In the Backup & Restore section, tap Back Up to iCloud.

    Check: The iCloud Backup page opens with My Backup selected in the Destination selector. Below it are the field Name (optional), the Back Up Now button and the Backups in iCloud list. While no backup exists, the list shows No backup in iCloud yet.

  3. Optional: tap Name (optional) and enter a name for the backup, for example Before moving.

    Check: The field shows the name. A name can have up to 60 characters; a longer entry is cut off.

  4. Tap Back Up Now.

    Check: A spinner appears beside the button. When the backup is complete, the page shows the green text Backed up 3 recorders · 2 cameras to iCloud., the name field is empty again, and the new backup appears at the top of Backups in iCloud. The earlier backups stay in the list.

Making the copy for Apple TV

  1. On the iCloud Backup page, select Apple TV in Destination.

    Check: The explanation below the selector reads A separate copy for Apple TV to restore. Apple TV can restore only this copy. The Current Backup section shows Last backed up and Devices of the Apple TV copy, or No backup in iCloud yet. The name field and the list are not shown.

  2. Tap Back Up Now.

    Check: The page shows the green success message, and Current Backup shows the new Last backed up time and the number of devices. The new copy replaces the previous Apple TV copy.

  • The two destinations are independent. Each Back Up Now to My Backup adds a backup and keeps the earlier ones until they are deleted (see “Several named backups: renaming and deleting”). The Apple TV destination keeps one copy, which each new backup replaces. Backing up to one destination does not change the other.
  • An iPhone and an iPad can restore any backup; an Apple TV can restore only the Apple TV copy. After devices or walls have been changed on an iPhone or iPad, back up to Apple TV again so that the television receives the new content.
  • The backup space is limited. All backups together, every backup of My Backup and the Apple TV copy, share about 1 MB of iCloud space. Tile pictures take most of it. When the space is full, the page shows Cam Hub's backup space in iCloud is full. Delete an older backup or remove some slot images, then try again.
  • When this device is not signed in to iCloud, the page shows the orange text Saved on this device only. Sign in to iCloud to keep a copy in the cloud. When the backup cannot be stored, it shows Couldn't save the backup. Check that you're signed in to iCloud. or Backup failed. Make sure you're signed in to iCloud and try again.
  • Back up before deleting all data. Delete All Data removes every device and saved password from this device. iCloud backups are not affected and can be restored afterwards as described in “Restoring from iCloud”. Without an iCloud backup, the device passwords cannot be recovered. See Chapter 13, “Settings”.
How a backup is encrypted and protected

A backup is stored encrypted in the private iCloud of the user and is synced only to devices that use the same Apple Account. A backup has no PIN. The encryption key is built into the app and is the same in every installation, so every one of one's own devices can restore without a password to remember. The key only prevents the backup from being stored as plain text; it is not a secret kept from someone who obtains both the backup and the app. The protection of a backup rests on the security of the Apple Account and of iCloud, so the Apple Account must be kept secure.

Several named backups: renaming and deleting

The Backups in iCloud list under My Backup shows every backup, newest first. A named backup shows its name, with the date and time and the contents below it, for example Oct 28, 2026 at 9:41 PM · 3 recorders · 2 cameras. A backup without a name shows the date and time, with the contents below. The same list, with the same actions, appears on the Restore from iCloud page; see “Restoring from iCloud”. The Apple TV copy has no name and does not appear in the list.

Renaming a backup

  1. On the iCloud Backup page with My Backup selected, swipe left on a backup in Backups in iCloud.

    Check: The buttons Rename and Delete appear at the right of the row. Touching and holding the row opens a menu with the same two actions.

  2. Tap Rename.

    Check: The dialog Rename Backup appears, with the field Name holding the current name and the buttons Save and Cancel.

  3. Enter the new name and tap Save.

    Check: The row shows the new name. When the field is left empty, the name is removed and the row shows the date and time again.

Deleting one backup

  1. Swipe left on the backup to delete.

    Check: The buttons Rename and Delete appear.

  2. Tap Delete.

    Check: The dialog Delete this backup? appears and explains that the backup is removed from iCloud permanently, that other signed-in devices lose it when they next sync, and that the devices and settings on this device are not affected.

  3. Tap Delete in the dialog.

    Check: The backup disappears from the list. The other backups, the Apple TV copy and the devices on this device are unchanged.

  • Spaces at the start and end of a name are removed. Renaming changes only the name; the contents and the date of the backup stay the same.
  • Backups made, renamed or deleted on another device with the same Apple Account appear in the list when iCloud has synced them, also while the page is open.
  • A backup made with an earlier version of Cam Hub appears in the list as one of the backups.
  • When a new name cannot be stored, the alert Couldn't save the backup. Check that you're signed in to iCloud. appears.
  • To delete every backup at once, see “Deleting all iCloud backups”.

Restoring from iCloud

Prerequisite: this device is signed in with the Apple Account to which the backups belong, and a backup exists in iCloud. Right after a backup, it can take some time before it syncs to another device.

  1. Tap the Settings tab at the bottom of the screen.

    Check: The screen shows the settings list.

  2. In the Backup & Restore section, tap Restore from iCloud.

    Check: The Restore from iCloud page opens with My Backup selected in the Source selector, the Choose a Backup list and the Restore button. The newest backup is marked with a checkmark. When no backup is found, the list shows No backup found in iCloud. Back up from your iPhone first, signed in to the same Apple Account. and the Restore button is unavailable.

  3. Tap the backup to restore.

    Check: The checkmark moves to that backup.

  4. Tap Restore.

    Check: A spinner appears beside the button. When the restore is complete, the page shows the green text Restored 5 devices.

To restore the Apple TV copy on an iPhone or iPad, select Apple TV in Source: the iCloud Backup section shows the time of creation (From) and the number of Devices of that copy; then tap Restore. In the Choose a Backup list, backups can be renamed and deleted with a swipe, as described in “Several named backups: renaming and deleting”.

  • When the backup that carries the checkmark is deleted, on this page or on another device, the checkmark disappears and Restore is unavailable until another backup in Choose a Backup is tapped.
  • Devices are merged: a device that matches a device already on this device is updated, including the names and the enabled state of its channels and the SNMP settings of a NAS; the other devices are added. Other devices already present are not deleted. The HTTPS setting follows the rule in “What backups and codes contain”.
  • App settings: the settings in the backup replace the matching settings on this device, including the LiveView Mix pages, Open on launch and the language. Settings that are not in the backup stay unchanged. A tile that shows a camera that was not restored becomes an empty tile, and every other tile keeps its place; empty tiles, control panels, clocks, labels and picture tiles are kept.
  • The enabled state of channels is checked against the current plan of this device. When a plan is held, channels beyond its allowance are shown as Disabled after the restore. On the free plan, the enabled state of the backup is kept, and channels beyond the free allowance show Not in your plan and a lock until the plan is restored or a plan is taken. For the allowances, see Chapter 11, “Plans and limits”.
  • The orange text Some passwords could not be saved on this device. Open those devices and use Edit Credentials. means that the passwords of some devices could not be stored. Enter them again as described in “Changing the user name and password of a device”.
  • This backup couldn't be read. Back up again to replace it. means that the backup is damaged, or that it was created by an older app with a PIN. Back up again on the original device.
  • No backup available to restore. and Restore failed. Please try again. mean that no readable backup exists, or that the restore failed. Check that iCloud is signed in and synced, then try again.

Deleting all iCloud backups

This action removes every backup at once. To delete a single backup, swipe it in the list as described in “Several named backups: renaming and deleting”.

  1. Tap the Settings tab, then tap Delete iCloud Backup in the Reset section.

    Check: The dialog Delete iCloud backup? appears and explains that all encrypted backups, including the Apple TV copy, are removed from iCloud permanently. While no backup exists, the row is unavailable.

  2. Tap Delete iCloud Backup in the dialog.

    Check: The dialog closes and the row Delete iCloud Backup becomes unavailable.

  • On an iPhone or iPad this action deletes every backup in iCloud: all backups of My Backup and the separate copy made for Apple TV. The same row on an Apple TV deletes only the copy made for Apple TV.
  • Other devices signed in with the same Apple Account lose the backups when they next sync. The devices and settings on this device are not affected.
  • When iCloud is not signed in, the action clears only the copy on this device, and the backups in the cloud can remain until the sign-in.

Moving devices and walls to a new phone

The LiveView Mix pages and their control panels belong to the app settings. Both methods below carry them: an iCloud backup always includes them, and a sharing code needs Include app settings to be on and Also Use Their Settings to be chosen on the new phone.

Method 1: moving with an iCloud backup (recommended)

Prerequisite: Cam Hub is installed on the new phone, which is signed in to iCloud with the same Apple Account.

  1. On the old phone, open the Settings tab and tap Back Up to iCloud.

    Check: The iCloud Backup page opens. A name entered in Name (optional), for example Old iPhone, identifies the backup in the list later.

  2. Make sure Destination is My Backup and tap Back Up Now.

    Check: The page shows the green success message, and the new backup appears at the top of Backups in iCloud.

  3. On the new phone, open Cam Hub, tap the Settings tab, then tap Restore from iCloud.

    Check: The Restore from iCloud page opens. With Source set to My Backup, the Choose a Backup list shows the backups, and the newest one is selected. When the backup of the old phone has not synced yet, open the page again a little later.

  4. Make sure the backup of the old phone carries the checkmark, then tap Restore.

    Check: The page shows Restored 5 devices. The LiveView Mix tab shows the wall of the old phone.

  5. On the new phone, tap Restore Purchases in the Settings tab.

    Check: Purchases restored. appears. The plan is not part of the backup and is retrieved this way; see “Subscribing, restoring purchases and redeeming a code”.

Method 2: moving with a sharing code

  1. On the old phone, open the Settings tab and tap Export Cameras.

    Check: The Export Cameras page opens, with every device ticked by default.

  2. Turn on Include app settings.

    Check: The switch is on, and the LiveView Mix pages and the control panels travel with the code.

  3. Optional: set a PIN or a password as described in “Locking a code”.

    Check: The export button becomes available once the entry is complete.

  4. Tap the export button, then tap Share and send the link to the new phone.

    Check: The system share sheet has sent the link. Send the PIN or the password by another channel.

  5. On the new phone, tap the received link, tap Import Cameras and, for a locked code, enter the PIN or the password.

    Check: The dialog This code also has the sender's app settings appears.

  6. Tap Also Use Their Settings.

    Check: The screen shows Added 5 cameras. The LiveView Mix tab shows the wall of the old phone.

Neither method carries the plan. After signing in with the same Apple Account, retrieve it on the new phone with Restore Purchases; see “Subscribing, restoring purchases and redeeming a code”.

Bringing the setup to Apple TV

On Apple TV a wall can only be given its cameras, each in SD or HD, a layout and black bars (see “The LiveView Mix tab”); arranging a wall, editing its tiles, drawing a custom layout and creating control panels are done on an iPhone or iPad, and entering a long code with the remote is laborious. The recommended approach is to finish the setup on an iPhone or iPad first. A backup made with Apple TV as the destination (see “Backing up to iCloud”) or a sharing code (see “Exporting cameras (creating a code)”) then brings the devices and the wall to the television. Apple TV restores only the Apple TV copy, not the backups of My Backup, and shows YouTube and Twitch streams by name only. The steps for the Apple TV, and what differs there, are described in Chapter 14, “Apple TV”.
