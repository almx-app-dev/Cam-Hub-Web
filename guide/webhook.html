9Control panels and webhooks

A control panel is a tile on a LiveView Mix wall that holds a row of buttons. Each button sends an HTTP request to an address of choice when pressed, which suits a Home Assistant webhook or service call, a relay board, Node-RED, or any other HTTP service the phone can reach. The same buttons can also be pressed on an Apple Watch.

What a control panel does

A control panel consists of a title, a number of buttons and an optional clock. Each button stores one complete HTTP request: method, URL, headers and body. When a button is pressed, the request goes directly from this iPhone, iPad or Apple TV to the address, without passing through a Cam Hub server. A button pressed on an Apple Watch is sent by the watch itself or through the paired iPhone; see “Buttons on Apple Watch”.

  • Cam Hub only sends the request. The URL and the content are entirely the choice of the user. Cam Hub does not check what kind of service answers, and it is not a dedicated controller for any smart-home product.
  • A request is sent only when a button is pressed on the wall or on the watch. Tapping a panel on the arrange screen opens its editor and sends nothing.
  • Control panels are created and edited on iPhone and iPad. Apple TV displays and runs the panels of the landscape page; see “How a panel looks on the wall”. Apple Watch shows their buttons; see “Buttons on Apple Watch”.
A control panel uses one camera allowance

Each control panel uses one camera allowance of the plan, from what the cameras leave of it, so a panel never takes a picture away from a camera. When the allowance is not sufficient, the panel is locked and its buttons are unavailable, on the wall and on the watch. For details, see “How plan limits affect the wall” and “What uses allowance”.

Adding a control panel to the wall

Prerequisite: LiveView Mix has been set up and the wall holds at least one camera; for the setup, see “Building a first wall of six cameras”. While it has not been set up, Arrange the wall can also be reached through Settings › LiveView Mix as soon as a device has been added. A control panel can be placed on the landscape page, on the portrait page or on either canvas of an iPhone Duo; the steps are the same.

  1. Tap the LiveView Mix tab at the bottom of the screen.

    Check: The screen shows the preview wall, with three buttons in the top-right corner.

  2. Tap the Adjust the Layout button, the rightmost of the three buttons in the top-right corner.

    Check: The Adjust the Layout page opens.

  3. Tap Arrange the wall.

    Check: The Arrange page opens: the canvas of the wall is at the top, and the Order list below it lists every filled tile under its number.

  4. Tap an unused tile on the canvas, shown with a dashed outline and a +. When the unused tiles are on another wall page, use the arrows below the canvas or swipe sideways first.

    Check: A menu titled with the tile number appears, for example Slot 9.

  5. Tap Picture, control panel, clock or label….

    Check: The editor of the tile opens from the bottom of the screen, titled Slot 9. The first row is Shows, and its current value is Empty.

  6. Tap Shows and select Control in the menu.

    Check: The page shows the three sections Template, Panel and Buttons. The template is Gate / Shutter, the panel title is Gate (in the language of the app), and the button section holds three buttons, each with No endpoint set in orange below it.

  7. Tap Template and select the closest type.

    Check: The button section is replaced by the default buttons of that template. For the content of the templates, see “Templates”.

  8. In the Panel section, enter the name of the panel in the Title field.

    Check: The field shows the name, which is later displayed above the buttons of the panel.

  9. Optional: tap Color and select the color of the border and the buttons.

    Check: The color icon shows the selected color. The default is cyan.

  10. Optional: turn on Show the time.

    Check: Four switches appear: Seconds, Date, Day of the week and 24-hour. The clock is shown in the space below the buttons.

  11. Set the URL and the content of every button as described in “Setting up a button”.

    Check: Every row of the button section shows the host name of the URL below its label, instead of No endpoint set.

  12. Tap Done in the top-right corner of the tile editor.

    Check: The screen returns to the Arrange page, and the tile on the canvas shows the panel as it appears on the wall.

  13. Tap Done in the top-right corner of the Arrange page.

    Check: The screen returns to the Adjust the Layout page.

  14. Tap Done in the top-right corner of the Adjust the Layout page.

    Check: The screen returns to the LiveView Mix tab, and the preview wall shows the new control panel.

  • When every tile of the layout is filled, the canvas shows no unused tile. Select a layout with more tiles in the layout row at the top of the Arrange page, or empty a tile, first; see “Arranging the wall and its tiles”.
  • A panel that already exists on the other page can be copied instead of being built again; see “The portrait page”. A panel on another wall page can be moved into an empty tile; see “Moving a tile into an empty tile”.
  • Tapping Cancel in the top-left corner of the tile editor restores the whole wall to the state it had when the editor was opened, including every change to the buttons.
  • Changing Shows to another item clears the title and all buttons of the panel. To remove the panel, set Shows to Empty, or swipe its row to the left in the Order list on the Arrange page and tap Delete. Either way the tile becomes empty and no other tile moves.
  • For picture, clock and label tiles, see “What a tile can show besides a camera”.
  • When Arrange the wall is reached through Settings › LiveView Mix, the operation that follows is the same.

Setting up a button

Prerequisite: the editor of the tile is open as described in “Adding a control panel to the wall”, and Control is selected.

  1. In the Buttons section, tap the button to set up. To create a new button, tap Add Button first, then tap the new row.

    Check: The screen shows the editor of that button. Its title is the label of the button, and the top-left corner holds only a back arrow.

  2. In the row of icons below the Icon row, tap the icon to use, or type the name of an SF Symbols icon in the field on the right.

    Check: The Icon row shows the selected icon and its name, for example arrow.up.to.line.

  3. Enter the text to show below the icon in the Label field.

    Check: The field shows the text. The title of the page changes to the same text.

  4. For a button that must be confirmed before it runs, turn on Confirm before firing.

    Check: The switch is on. A confirmation box now appears when the button is pressed, on the wall and on the watch; see “Pressing a button and reading the result”.

  5. In the Request section, select GET, POST, PUT or DELETE in the Method menu.

    Check: The menu shows the selected method. With GET, the Body section is absent from the lower part of the page; the other three methods show it.

  6. Enter the complete URL in the field below Method, beginning with http:// or https://.

    Check: The field shows the URL.

  7. On an iPhone, optional: in the Apple Watch section, tap How it is sent and select Automatic, Watch directly or Through iPhone.

    Check: The menu shows the choice, and the note below it explains what the choice does. For the meaning of each choice, see “Buttons on Apple Watch”.

  8. When a header is needed, tap Add Header and enter the name and the value of the header in the Name and Value fields.

    Check: The Headers section gains a row, and both fields show the text entered. Repeat the step for further headers; swipe a row to the left to delete the header.

  9. When content must be sent, confirm the content type in the upper field of the Body section (application/json by default), then enter the content in the text box below it.

    Check: The text box shows the content. The content is sent exactly as typed.

  10. Tap the back arrow in the top-left corner.

    Check: The screen returns to the tile editor, and the row of the button shows the host name of the URL below its label.

Pressing a button and reading the result

Buttons can be pressed on the preview wall of the LiveView Mix tab and on the full-screen wall. A newly configured button has no separate test function; pressing it once serves as the test, followed by a check on the receiving side that the request arrived.

  1. On the preview wall or the full-screen wall, tap a button of the panel.

    Check: A button without Confirm before firing changes its icon to a spinner immediately, which means that the request has been sent. A button with it on opens a confirmation box beside the panel, titled with the panel title (or Run this action? when the panel has no title).

  2. When the confirmation box appears, tap the red button in it, which carries the label of the pressed button. To cancel, tap anywhere outside the box.

    Check: The box closes and the icon changes to a spinner. When canceled, no request is sent.

  3. Watch the icon of the button.

    Check: Depending on the result, the icon changes to a green check mark or an orange warning triangle, and returns to the original icon after about 1.6 seconds.

The button showsMeaning
The configured iconIdle, or the result has been displayed.
A spinnerThe request has been sent and the answer is awaited. When no answer arrives within 10 seconds, the request counts as failed.
A green check markThe receiving side answered with a status code from 200 to 299. Redirects are followed automatically, and the final answer decides.
An orange warning triangleThe request did not succeed. The cause can be an empty or malformed URL, no connection, a timeout, an untrusted certificate, or a status code outside 200 to 299, for example 401, 404 or 500. The screen does not show the cause, and no log is kept.
  • A green check mark only means that the receiving side answered successfully. It does not prove that the equipment moved. To verify the outcome, look at the log of the receiving side.
  • Every press sends one request, and nothing prevents repeated presses. Pressing twice in a row sends two requests. Buttons that make physical equipment move should have Confirm before firing on.
  • When the orange triangle appears repeatedly, check in this order: whether the URL is valid, whether the phone and the receiving side are on the same network or can reach each other, and whether the address of the receiving side can be resolved. When the receiving side is on the local network, Cam Hub must be allowed to access the local network; see “Finding devices with the network scan”. For other problems, see Chapter 15, “Troubleshooting”.
  • For pressing buttons on an Apple Watch, see “Buttons on Apple Watch”.

How a panel looks on the wall

  • Button layout: 1 button is placed in 1 column, 2 buttons in 2 columns, 3 buttons in 3 columns, 4 buttons as 2 × 2, and 5 or more buttons in 3 columns.
  • Small tiles: the panel shrinks automatically. The clock is hidden first, then the labels below the icons; the title and the icons remain.
  • Plan: each control panel uses one camera allowance, from what the cameras leave of it. A panel beyond the allowance shows a lock, its title and Not in your plan, and its buttons are unavailable; on the preview, the tile shows a lock and Not in your plan. Each panel on each wall counts on its own: the landscape page always, the portrait page while it is switched on and the lower canvas of an iPhone Duo while the two canvases are switched on; a copied panel counts separately from its original. Clock, label, picture and empty tiles use no allowance. A subscription to an NVR plan alone does not raise the allowance available to panels. For the counting rules, see “How plan limits affect the wall” and “What uses allowance”.
  • Apple TV: a panel is created on an iPhone or an iPad, and the panels of the landscape page are shown on the wall of the Apple TV; see Chapter 14, “Apple TV”.
  • Apple Watch: the buttons of every panel that the plan covers appear on the paired Apple Watch; see “Buttons on Apple Watch”.
  • Backup and sharing: the settings of a panel, including the values of headers, belong to the app settings. They enter every iCloud backup, and they also enter a sharing code when Include app settings is on during export; see Chapter 10, “Sharing and backup”.

Buttons on Apple Watch

Cam Hub on Apple Watch shows the buttons of the control panels that are set up on the paired iPhone, and fires a button with one tap. It shows nothing else: no video and no cameras. The watch app has no settings, sign-in or purchase of its own; the iPhone decides which buttons it shows.

  • Which buttons: every button with a valid URL, of every control panel that the plan covers: the landscape page, the portrait page while it is switched on, and the lower canvas of an iPhone Duo while the two canvases are switched on. A button of the portrait page that is identical to one on the landscape page (same panel title, label and request) is listed once.
  • The list: the screen is titled Controls. Buttons are grouped under the titles of their panels, in the order of the wall. Each row shows the icon in the color of the panel and the label of the button (the URL when the label is empty).
  • Keeping in step: when a panel or a button is changed on the iPhone, or the plan changes, the iPhone sends the watch a new list. A panel that the plan no longer covers disappears from the watch.
  • Working on its own: the list is kept on the watch. The watch app opens and shows it even when the iPhone app is not running or the iPhone is out of reach; buttons that the watch may send itself still work then.
  • Language: the watch shows its texts and the default words of the panels in the language of the iPhone app, not the language of the watch.
  • Before the first buttons arrive: the watch shows No buttons yet with a note that the buttons of a control panel added to LiveView Mix on the iPhone appear there.

How a press is sent

Each button has its own choice under How it is sent in the button editor on the iPhone (see “Setting up a button”):

ChoiceWhat happens on a press
Automatic (default)A public address is sent straight from the watch. A home-network or VPN address, for example 192.168.x.x or a name ending in .local, goes through the iPhone first, which can reach it.
Watch directlyThe watch always sends the request itself, over its own Wi-Fi or cellular connection or over the connection of the iPhone. This is the fastest way, but a home-network or VPN address may be out of reach of the watch.
Through iPhoneFor a server that can only be reached through a VPN on the iPhone, especially when its address looks public: the watch has no VPN of its own. The watch sends the request itself only when the iPhone is out of reach.
  • When a press goes through the iPhone, the watch first checks that the iPhone answers, waiting up to about 6 seconds; the iPhone app can be started in the background for this. The iPhone then sends the request in the same way as its wall does, after checking that the plan still covers the panel.
  • When the iPhone does not answer that check, the watch sends the request itself. When the iPhone took the request but its answer was lost, the press is shown as failed and is not sent again, so a switch is never toggled twice.
  • A request that the watch sent itself and that failed is not repeated through the iPhone. A request from the watch to a home-network address only works while the watch is on the same Wi-Fi network.

Pressing a button on the watch

Prerequisite: Cam Hub is installed on the Apple Watch that is paired with the iPhone, and at least one control panel with a valid URL is on the wall.

  1. Open Cam Hub on the Apple Watch.

    Check: The watch shows Controls and the buttons, grouped by panel.

  2. Tap a button.

    Check: A button without Confirm before firing shows a spinner at the end of its row at once. A button with it on asks Run this action?, with the panel title below, a red button carrying the label of the button and Cancel.

  3. When the question appears, tap the red button. To cancel, tap Cancel.

    Check: The question closes and the row shows a spinner. When canceled, nothing is sent.

  4. Watch the end of the row.

    Check: A green check mark means that the endpoint answered successfully; a red warning triangle means that the request did not succeed. The watch taps the wrist as well, and the row returns to normal after about 2.5 seconds.

A tap on a button that is still sending is ignored, so an impatient second tap does not send the request twice. As on the wall, a green check mark only means that the receiving side answered; it does not prove that the equipment moved.

Using Home Assistant

The following two approaches use Home Assistant as the example. The address homeassistant.local, the identifier gate-open-7f3c9a21 and the entity name cover.gate are sample values and must be replaced with the real ones. The behavior on the Home Assistant side is defined by its own documentation and can change between versions.

Prerequisites: Home Assistant runs on the home network and the phone can reach its address; a tile of the LiveView Mix wall has Control selected (see “Adding a control panel to the wall”). Home Assistant uses http and port 8123 by default. The sample text in the URL field of the app begins with https and must be changed to match the real setup.

Approach 1: webhook trigger (no token needed)

  1. In Home Assistant, create a new automation.

    Check: The screen shows the editor of the automation.

  2. Select Webhook as the trigger and enter an identifier that is hard to guess, for example gate-open-7f3c9a21.

    Check: The editor shows the identifier. The identifier works like a password: anyone who knows it and the address can start the automation.

  3. Set the action, for example the entity that opens the gate, and save the automation.

    Check: The automation appears in the list of automations of Home Assistant.

  4. In Cam Hub, open the editor of the button to use, as described in step 1 of “Setting up a button”.

    Check: The screen shows the editor of that button.

  5. Select POST as the Method and enter http://homeassistant.local:8123/api/webhook/gate-open-7f3c9a21 in the URL field. Headers and body can stay empty.

    Check: The field shows the URL, and after returning, the row of the button shows the host name homeassistant.local.

  6. Return to the wall and press the button.

    Check: The icon shows a spinner first, then a green check mark.

  7. In Home Assistant, open the run log of the automation.

    Check: The log shows the run that the press started. Home Assistant can also answer successfully for an identifier that does not exist, so the run log decides, not the green check mark.

The equivalent request is:

POST /api/webhook/gate-open-7f3c9a21 HTTP/1.1
Host: homeassistant.local:8123

The automation can also be written as a configuration file. The following example is for comparison only, and the syntax depends on the version of Home Assistant:

triggers:
  - trigger: webhook
    webhook_id: gate-open-7f3c9a21
    allowed_methods:
      - POST
    local_only: true
actions:
  - action: cover.open_cover
    target:
      entity_id: cover.gate

A webhook trigger accepts only POST and PUT by default, and by default only requests from the local network. Using it from an outside network needs separate measures; see “Security notes”. A button pressed on an Apple Watch reaches an address such as homeassistant.local through the iPhone when How it is sent is Automatic or Through iPhone; see “Buttons on Apple Watch”.

Approach 2: service call (token needed)

  1. On the profile page of Home Assistant, create a long-lived access token and copy it immediately.

    Check: The screen shows the token. A token is usually displayed in full only once, when it is created.

  2. In Cam Hub, open the editor of the button, select POST as the Method and enter http://homeassistant.local:8123/api/services/cover/open_cover in the URL field.

    Check: The field shows the URL.

  3. Tap Add Header.

    Check: The Headers section gains a row with the two fields Name and Value.

  4. Enter Authorization in the Name field, and Bearer, a space and the copied token in the Value field.

    Check: Both fields show the text entered. The value of the header is displayed in plain text.

  5. In the Body section, confirm that the content type is application/json and enter {"entity_id":"cover.gate"} in the text box.

    Check: The text box shows the content.

  6. Return to the wall and press the button.

    Check: The icon shows a spinner first, then a green check mark. The log of Home Assistant shows that the service was called.

The equivalent request is:

POST /api/services/cover/open_cover HTTP/1.1
Host: homeassistant.local:8123
Authorization: Bearer <long-lived access token>
Content-Type: application/json

{"entity_id":"cover.gate"}
Prefer the webhook trigger

When a webhook identifier leaks, the effect is limited to the one automation it belongs to. A long-lived access token can operate the whole of Home Assistant. For any action that approach 1 can perform, use approach 1.

Security notes

TopicDescription and recommendation
HTTP and HTTPSA request sent with http:// is not encrypted. Anyone on the same network path can read the URL, the token in a header and the body. Use HTTP only inside a trusted home network and for webhooks that carry no sensitive data. Whenever a request carries a token or leaves the home network, use https://.
HTTPS certificatesCam Hub has no option to trust a self-signed certificate. An https:// address with a self-signed certificate fails, and the button shows the orange triangle. Inside the local network, http:// can be used instead, or a certificate that the phone trusts can be installed on the receiving side.
Storage of tokens and identifiersThe values of headers are displayed in plain text in the editor and are stored in plain text in the app settings of this device.
Apple WatchThe buttons that reach the watch carry their whole request, including the URL, the headers and the body. They are copied to the paired Apple Watch and kept there, so a token in a header is stored on the watch as well.
Backups and sharing codesThe settings of a panel enter every iCloud backup, and every sharing code exported with Include app settings on. Treat such a code like a password and lock it with a PIN or a password; see “Locking a code”. When a token has been exposed, revoke it on the receiving side and create a new one.
Outside networksOpening port 8123 of Home Assistant directly to the internet is not recommended. How you reach it when away from home, for example through a VPN or the official remote-access method of Home Assistant, is your own choice; change the URL to the matching address.
Physical actionsTurn on Confirm before firing for buttons that open doors, unlock and sound alarms. Cam Hub has no further lock on panel buttons; anyone who can operate the unlocked device, or the watch, can press them.
Name resolutionNames ending in .local may not resolve on some networks. When connections fail, enter the fixed IP address of the receiving side instead.
