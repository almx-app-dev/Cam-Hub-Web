3기기 추가

카메라나 녹화기를 추가하려면 주소와 계정이 필요합니다. 기기에 연결하는 방법은 Cam Hub가 직접 알아내며, 대신 고급에서 연결 방식과 포트를 선택할 수도 있습니다. YouTube 라이브 스트림과 Twitch 채널은 별도의 화면에서 추가합니다.

기기 추가 양식

고급 › HTTP 포트기기 제어 인터페이스의 포트입니다. 자동 감지를 사용하면 Cam Hub가 열려 있는 포트를 직접 찾으며, 이곳에 입력한 포트를 먼저 시도합니다. ONVIF를 사용할 때는 기기의 ONVIF 서비스 포트를 입력해야 합니다. 예를 들어 일부 기기는 2020이나 8899를 사용합니다. HTTPS 사용이 켜져 있으면 기기에는 대신 HTTPS 포트로 접속하며, 이 입력란의 포트는 나중에 HTTPS를 끌 경우에 대비해 유지됩니다.80
고급 › RTSP 포트영상 스트림의 포트입니다. 자동 감지는 이곳에 입력한 포트를 먼저 시도합니다. RTSP 포트가 554가 아닌 브랜드를 선택하면, 입력란에 이전 기본값이 그대로 있는 한 그 브랜드의 포트가 채워집니다.554

고급 › 기기 포트특정 기기 제품군의 자체 프로토콜을 선택하면 위의 두 포트 대신 표시됩니다. 기기가 그 프로토콜로 응답하는 포트입니다.34567

  1. 화면 아래의 기기 탭을 선택합니다.

    확인: 기기 목록이 표시됩니다.

  2. 오른쪽 위의 ＋ 버튼을 탭합니다. 목록이 비어 있을 때는 화면 가운데의 기기 추가 버튼을 탭하면 양식이 바로 열립니다.

    확인: 기기 추가와, 제공되는 지역에서는 YouTube 라이브 스트림, Twitch 채널이 포함된 메뉴가 열립니다.

  3. 기기 추가를 선택합니다.

    확인: 기기와 인증 정보 섹션, 접혀 있는 고급 섹션이 있는 기기 추가 양식이 표시됩니다.

  4. 선택 사항: 이름(선택) 입력란에 기기의 이름을 입력합니다.

    확인: 입력란에 이름이 표시되며, 이 이름은 나중에 기기 목록에 표시됩니다.

  5. IP 주소 또는 호스트 이름 입력란에 기기의 주소를 입력합니다(예: 192.168.1.64).

    확인: 오른쪽 위의 추가 버튼이 활성화됩니다.

  6. 사용자 이름과 비밀번호 입력란에 기기의 계정 정보를 입력합니다.

    확인: 두 입력란이 모두 채워집니다. 비밀번호는 점으로 가려집니다.

  7. 오른쪽 위의 추가를 탭합니다.

    확인: 양식에 기기에 연결 중… 문구가 표시되고 그 아래에 현재 단계(예: 열려 있는 포트를 찾는 중… 또는 포트 8899에서 ONVIF 시도 중…)가 표시됩니다. 연결에 성공하면 양식이 닫히고 새 기기가 기기 목록에 나타납니다.

연결하는 동안에는 추가 버튼 자리에 진행 표시기가 나타나며, 아래로 쓸어내려도 양식이 닫히지 않습니다. 취소를 탭하면 시도가 중단되고 아무것도 저장되지 않습니다. 연결한 뒤 Cam Hub는 기기가 녹화기인지 단일 카메라인지 식별하고, 채널 목록을 읽은 다음 기기를 저장합니다.

새 기기가 Cam Hub에서 SNMP로 디스크 정보를 읽을 수 있는 네트워크 저장 장치(NAS)이면 이어서 SNMP 설정 시트가 나타납니다. 이 단계는 선택 사항입니다. 나중에를 탭하면 시트가 닫히며, SNMP는 나중에 디스크 상태 페이지에서 설정할 수 있습니다. 자세한 내용은 ‘디스크 상태’ 참조. 어느 쪽이든 기기는 저장됩니다.

요금제 한도 이내의 채널만 활성화됩니다. 신호가 있다고 알려 오는 채널이 먼저 한도를 받고, 그다음에 신호가 없는 채널이 받으며, 각 그룹 안에서는 기기의 순서를 따릅니다. 나머지 채널은 비활성화됨으로 표시됩니다. 자세한 내용은 ‘요금제 한도와 채널 활성화’ 참조. 요금제에서 허용하는 녹화기 수에 도달하면 요금제 페이지가 열립니다. 데모 기기가 무료 버전의 녹화기 자리를 차지하고 있으면 페이지에 그 사실이 표시되며, 데모 기기를 삭제하면 자리가 비워집니다. YouTube 라이브 스트림과 Twitch 채널은 요금제 한도에 포함되지 않습니다. 한도에 대해서는 11장 ‘요금제와 한도’ 참조.

저장된 기기의 주소는 수정할 수 없습니다

저장된 기기는 이름을 변경할 수 있고, 인증 정보 편집으로 사용자 이름과 비밀번호를 변경할 수 있습니다. 자세한 내용은 ‘기기의 사용자 이름과 비밀번호 변경’ 참조. 주소는 변경할 수 없습니다. IP 주소가 바뀌면 새 주소는 다른 기기로 취급되며, 녹화기는 녹화기 한도에도 포함됩니다. 이 경우 먼저 이전 기기를 삭제하고(4장 ‘기기 탭과 채널’ 참조) 새 주소를 추가합니다. 같은 주소, 포트, 사용자 이름으로 기기를 다시 추가하면 두 번째 기기가 만들어지지 않고 저장된 기기가 그 자리에서 갱신됩니다. 기존 채널의 스위치는 그대로 유지됩니다. 이름(선택)에 입력한 이름은 저장된 이름을 대체하며, 입력란이 비어 있으면 저장된 이름이 유지됩니다. 입력한 비밀번호는 저장된 비밀번호를 대체합니다. HTTPS 사용을 켜면 저장된 기기의 HTTPS가 켜지고, 켜지 않으면 기기의 HTTPS 설정은 그대로 유지됩니다.

브랜드를 선택하지 않고 추가하기

기본값인 자동 감지를 사용하면 Cam Hub에 필요한 것은 주소와 계정뿐입니다. 추가는 두 단계로 진행됩니다.

  1. 포트 확인. Cam Hub는 카메라와 녹화기가 흔히 사용하는 포트 가운데 해당 주소에서 열려 있는 포트를 확인합니다. 웹 및 제어 인터페이스, ONVIF, RTSP, 특정 기기 제품군의 자체 프로토콜에 쓰이는 포트가 대상입니다. 이 확인에서는 사용자 이름과 비밀번호를 보내지 않으므로 계정 잠금 횟수에 포함되지 않습니다. 아무것도 응답하지 않으면 대기 시간을 늘려 한 번 더 확인합니다.
  2. 연결 시도. 이어서 Cam Hub는 응답한 포트에서 앱에 내장된 제조사 프로토콜, 특정 기기 제품군의 자체 프로토콜, ONVIF, 일반 RTSP 순서로 각 연결 방법을 시도합니다. RTSP는 기기가 드러낸 브랜드의 스트림 경로, 대부분의 카메라가 쓰는 경로, 목록에 있는 모든 브랜드의 경로 순서로 시도합니다. 처음 연결에 성공한 방법이 연결된 포트와 함께 유지됩니다.
  • 고급에 입력한 포트를 먼저 시도합니다. 기본값(80 또는 554)과 다른 포트가 열려 있으면 그 포트만 사용합니다. 여러 기기를 포워딩하는 주소에서는 다른 포트가 다른 기기의 것일 수 있기 때문입니다.
  • 계정을 보호하기 위해, 제조사 프로토콜이 로그인을 거부하면 즉시 사용자 이름 또는 비밀번호가 올바르지 않습니다.로 시도를 끝냅니다. ONVIF와 RTSP는 별도의 계정을 사용할 수 있으므로 로그인이 두 번째로 거부된 뒤에 시도를 끝냅니다. 로그인이 거부된 뒤에는 스트림 경로를 한 번에 하나씩 시도합니다.
  • RTSP로만 연결되는 카메라는 항상 단일 카메라로 추가됩니다. RTSP만 제공하는 녹화기를 추가하려면 해당 브랜드를 선택하고 카메라 수를 입력합니다. 자세한 내용은 ‘연결 방식 선택’ 참조.
  • 특정 기기 제품군의 자체 프로토콜은 로컬 네트워크 안의 주소와 기본 포트에서만 자동으로 시도합니다. 이러한 기기가 로컬 네트워크 밖에 있거나 다른 포트를 사용하면 고급에서 해당 연결 방식을 선택합니다. 자세한 내용은 ‘연결 방식’ 참조.
  • 스트림 경로를 여러 개 시도하는 데는 시간이 걸립니다. 잘못된 경로에 응답하지 않는 카메라에서는 추가가 성공하거나 실패하기까지 1분 넘게 걸릴 수 있습니다.
  • 추가에 실패하면 오류 메시지 아래에 찾은 열린 포트가 표시되거나(예: 찾은 열린 포트: 80, 554), 양식에 이 주소에서 열려 있는 포트를 찾지 못했습니다.가 표시됩니다. 앞의 경우는 기기가 응답했지만 연결되지 않았다는 뜻이고, 뒤의 경우는 아무것도 응답하지 않았다는 뜻입니다.

자동 감지가 인식하는 브랜드와 정확한 시도 순서는 ‘연결 방식’에서 설명합니다.

연결 방식 선택

대부분의 기기에는 자동 감지가 적합합니다. 자동 감지로 기기를 찾을 수 없거나 특정 프로토콜을 사용하려면 고급에서 연결 방식을 선택합니다.

  1. 기기 추가 양식에서 고급을 탭합니다.

    확인: 섹션이 펼쳐지고 연결 방식, HTTP 포트, RTSP 포트와 HTTPS 사용 스위치가 표시됩니다.

  2. 연결 방식을 탭합니다.

    확인: 검색 입력란이 있는 연결 방식 목록이 열립니다. 맨 위에는 자동 감지, ONVIF, 특정 기기 제품군의 자체 프로토콜, RTSP가 있고, 그 아래의 브랜드에 지원 브랜드가 알파벳순으로 나열됩니다.

  3. 선택 사항: 검색 입력란에 브랜드 이름의 일부를 입력합니다.

    확인: 일치하는 항목만 목록에 표시됩니다. 해당 브랜드의 카메라가 판매되는 다른 이름으로도 브랜드를 찾을 수 있습니다.

  4. 연결 방식을 탭합니다.

    확인: 양식의 연결 방식 행에 선택한 방식이 표시되고 섹션 아래에 설명이 나타납니다. 목록의 브랜드나 RTSP를 선택하면 카메라와 경로 입력란이 있는 섹션이 추가되고, 특정 기기 제품군의 자체 프로토콜을 선택하면 두 포트 대신 기기 포트가 표시됩니다. HTTPS 사용은 자동 감지와 ONVIF에서만 제공됩니다.

  5. 기기가 기본 포트를 사용하지 않으면 포트 입력란을 변경합니다.

    확인: 입력란에 기기가 사용하는 포트가 표시됩니다.

선택할 수 있는 항목은 다음과 같습니다.

  • 자동 감지(기본값): ‘브랜드를 선택하지 않고 추가하기’에서 설명한 대로 Cam Hub가 포트와 프로토콜을 직접 찾습니다.
  • ONVIF: 감지를 건너뛰고 HTTP 포트에 입력한 포트(HTTPS 사용이 켜져 있으면 HTTPS 포트, ‘HTTPS로 기기 추가’ 참조)에서 개방형 ONVIF 프로토콜만 사용합니다. 자동 감지로 찾을 수 없는 카메라이거나 자체 프로토콜도 지원하는 기기에서 ONVIF를 사용하려는 경우에 선택합니다. 기기에서 ONVIF를 켜야 하며, 기기에 별도의 ONVIF 사용자 목록이 있으면 그곳에서 사용자를 만들어야 합니다. 녹화 재생과 PTZ 제어를 사용할 수 있는지는 기기가 제공하는 기능에 따라 다릅니다.
  • RTSP: 브랜드와 관계없이 카메라에 일반 RTSP로 연결하며, 대부분의 카메라가 쓰는 스트림 경로를 시도합니다. 어느 경로도 작동하지 않으면 카메라의 설명서나 웹 페이지에 나와 있는 경로를 입력합니다.
  • 특정 기기 제품군의 자체 프로토콜: 기기 포트에서 해당 프로토콜로 연결합니다. 포트를 변경하거나 포워딩하지 않았다면 34567입니다. 자동 감지로 찾을 수 없는 녹화기나 로컬 네트워크 밖에서 연결하는 녹화기에 사용합니다. 로컬 네트워크 밖의 주소이면 양식에 주황색 경고가 표시됩니다. 이 프로토콜은 영상을 암호화하지 않으며 많은 기기가 비밀번호를 약하게만 보호한다는 내용입니다. 외부에서 어떤 방식으로 연결할지(예: VPN 사용)는 직접 결정하면 됩니다. 기기 제품군의 이름은 ‘연결 방식’에 나와 있습니다.
  • 목록에 있는 브랜드: 해당 브랜드에 대해 문서화된 스트림 경로를 사용하여 RTSP로 직접 연결합니다. 기기에서 ONVIF가 꺼져 있을 때나 RTSP만 제공하는 녹화기를 추가할 때 사용합니다. 추가되는 섹션에는 두 입력란이 있습니다.
    • 카메라: 1에서 64 사이의 숫자입니다. 1이면 기기가 단일 카메라로 추가되고, 2 이상이면 녹화기로 추가되어 녹화기 한도에 포함됩니다. 채널 수를 알아낸 네트워크 검색 결과에서 양식을 열면 이 값이 채워집니다.
    • 경로 입력란: 비워 두면 Cam Hub가 해당 브랜드의 문서화된 경로를 차례로 시도하여 기기가 응답하는 경로를 유지합니다. 입력란에는 처음 시도할 경로가 표시됩니다. 특정 경로를 지정할 때만 입력합니다.

Cam Hub에 제조사 프로토콜이 내장된 브랜드는 목록에 없으며, 목록 아래의 안내대로 자동 감지가 이러한 기기를 찾습니다. 일부 브랜드는 RTSP가 작동하려면 제조사의 앱이나 웹 인터페이스에서 만든 전용 카메라 계정 또는 ONVIF 계정이 필요하며, 관리자 계정만으로는 거부될 수 있습니다. 일부 브랜드는 모델이나 펌웨어에 따라 경로가 달라서 첫 시도가 맞지 않을 수 있습니다. 양식은 이러한 참고 사항을 경로 입력란 아래에 표시합니다. 브랜드 목록과 브랜드별 참고 사항은 ‘목록의 브랜드’에서 설명합니다.

RTSP와 목록의 브랜드를 통한 연결은 실시간 보기만 제공합니다

이 연결 방식에는 녹화 재생, PTZ 제어, 스냅샷이 없습니다. SD는 기기가 해당 브랜드의 두 번째 스트림을 제공하면 그 스트림을 사용하고, 그렇지 않으면 HD와 같은 스트림을 표시합니다.

HTTPS를 켜지 않으면 기기 제어는 HTTP를 사용합니다

기기 제어(기기 식별, 채널 목록 읽기, 녹화 검색)는 http://address:port 형식을 사용하며, 기기에 HTTPS를 켠 경우에는 HTTPS를 사용합니다. 자체 프로토콜을 쓰는 기기 제품군은 대신 그 프로토콜을 사용합니다. HTTPS만 허용하는 기기는 HTTPS 사용을 켜고 추가합니다. 자세한 내용은 ‘HTTPS로 기기 추가’ 참조.

RTSP와 목록의 브랜드를 통한 연결은 실패 메시지가 다릅니다

기기에 연결할 수 없거나 시간이 초과되면 문제가 발생했습니다. 다시 시도하세요.만 표시됩니다. 이 연결 방식에서 지원되지 않는 기기입니다. 메시지는 후보 경로 중 어느 것에서도 스트림이 반환되지 않았다는 뜻입니다. 흔한 원인은 잘못된 RTSP 포트와 기기에서 꺼져 있는 영상 스트림입니다.

기기를 사용할 수 있는지 불분명하면 양식의 호환성 참고를 탭하여 지원되는 기기와 지원되지 않는 기기를 확인합니다. 기기의 브랜드를 알아낸 검색 결과에서 양식을 열고 주소를 바꾸지 않았다면 이 항목과 데모 카메라 추가는 표시되지 않습니다.

HTTPS로 기기 추가

웹 페이지가 HTTPS를 사용하는 기기는 HTTPS로 추가할 수 있으며, 일반 HTTP가 꺼져 있어도 마찬가지입니다. HTTPS는 직접 켜지 않는 한 꺼져 있고, 자동 감지와 ONVIF에서만 제공됩니다. 특정 기기 제품군의 자체 프로토콜, RTSP, 목록에 있는 브랜드에는 HTTPS로 보호할 웹 인터페이스가 없기 때문입니다. 이미 추가한 기기는 기기 페이지에서 HTTPS로 전환합니다. 자세한 내용은 ‘저장된 기기의 HTTPS’ 참조.

  1. 기기 추가 양식에서 주소, 사용자 이름, 비밀번호를 입력한 다음 고급을 탭합니다.

    확인: 섹션에 꺼져 있는 HTTPS 사용 스위치가 표시됩니다.

  2. HTTPS 사용을 켭니다.

    확인: 443이 입력된 HTTPS 포트 입력란이 나타나고, 섹션 아래에 이 옵션을 설명하는 안내문이 표시됩니다.

  3. 기기가 다른 HTTPS 포트를 사용하면 HTTPS 포트에 그 포트를 입력합니다.

    확인: 입력란에 포트가 표시됩니다. 443으로 두면 Cam Hub가 5001과 8443에서도 HTTPS를 찾으며, 그 밖의 포트를 입력하면 그 포트만 사용합니다.

  4. 오른쪽 위의 추가를 탭합니다.

    확인: 양식에 기기에 연결 중… 문구가 표시됩니다. 연결에 성공하면 양식이 닫히고 새 기기가 기기 목록에 나타납니다. 기기 페이지의 정보 카드에는 포트와 함께 HTTPS 행이 표시됩니다.

  • 안내문은 웹 페이지가 HTTPS를 사용하는 기기 전용입니다. 잘 모르겠으면 꺼 두세요. Cam Hub는 이 포트에서 HTTPS를 찾고(443 그대로 두면 5001과 8443도 시도합니다), 기기가 지금 제시하는 인증서를 신뢰합니다. 나중에 기기 페이지의 HTTPS에서 확인할 수 있습니다.입니다. 스위치가 켜져 있는 동안에는 고급을 접어도 계속 표시됩니다.
  • HTTPS를 찾을 때는 사용자 이름과 비밀번호를 보내지 않습니다. Cam Hub는 어떤 포트가 인증서를 제시하는지만 확인합니다. 인증서를 제시하는 포트가 없으면 양식에 이 기기가 방금 HTTPS로 응답하지 않았습니다. 문구가 표시됩니다. 여러 포트가 인증서를 제시하면 차례로 시도하므로, 다른 기기로 포워딩된 포트가 있어도 시도가 중단되지 않습니다.
  • 이 메시지가 표시되면 먼저 확인할 것에 일반적인 점검 항목이 나열됩니다. 자세한 내용은 ‘추가에 실패했을 때: 점검 목록’ 참조. 다음 사항도 확인합니다.
    • 브라우저에서 https://로 시작하는 주소로 기기의 웹 페이지를 열어, 기기가 HTTPS를 사용하는지와 어떤 포트를 사용하는지 확인합니다.
    • 그 포트를 HTTPS 포트에 입력합니다. 443으로 두면 443, 5001, 8443만 확인합니다.
    • 일반 HTTP로 기기를 추가하려면 HTTPS 사용을 끕니다.

    확인: 확인된 내용에 가능성이 있는 원인과 먼저 시도할 일이 쉬운 말로 나열됩니다. 눈에 띄는 문제가 없으면 눈에 띄는 문제는 없습니다. 문구가 표시됩니다.

    확인: 메일 작성 화면이 닫히고 보고서 페이지가 다시 표시됩니다.

  9. 오른쪽 위의 완료를 탭합니다.

    확인: 보고서 페이지가 닫히고 기기 추가 양식이 다시 표시됩니다.

  • 안내문을 한 번 확인한 뒤에는 보고서 페이지 맨 위에 짧은 알림만 표시되며, 이 기능에 대하여로 전체 안내문을 다시 읽을 수 있습니다.

  • 보고서는 전송할 때만 기기 밖으로 나갑니다. 이메일을 보내기로 선택하지 않는 한 아무것도 전송되지 않습니다. 비밀번호는 포함되지 않습니다.

로그인 동작

수집하는 동안 로그인이 필요한 요청은 기기가 인증 정보를 수락하거나 거부할 때까지 한 번에 하나씩 전송됩니다. 기기가 인증 정보를 거부한 뒤에는 보고서가 더 이상 로그인을 전송하지 않습니다. 보고서를 만들게 된 실패한 시도가 이미 로그인 거부(사용자 이름 또는 비밀번호가 올바르지 않습니다.)였다면 기기가 계정을 잠그지 않도록 보고서는 로그인을 전혀 시도하지 않습니다. HTTPS 사용이 켜져 있었다면 보고서는 먼저 로그인하지 않고 기기의 인증서를 찾은 다음, 그 인증서로 HTTPS를 통해 시도를 반복합니다. 기기가 인증서를 제시하지 않으면 보고서는 로그인하지 않습니다. 수집에서는 읽기 전용 요청만 전송하며 기기의 어떤 설정도 변경하지 않습니다.

보고서에 포함되는 내용과 포함되지 않는 내용

  • 포함되는 내용: 앱과 시스템의 버전, iPhone 또는 iPad의 모델 식별자, 언어 설정, 선택한 연결 방식(HTTPS 사용이 켜져 있었다면 HTTPS 포트 포함), 기기 주소(사설 네트워크 주소의 마지막 부분은 x로 가려지며, 공인 주소는 주소의 종류만 표시), 포트, 실패한 시도의 오류 코드, 감지된 브랜드와 모델, 열려 있는 포트, 기기 응답의 헤더와 구조(마스킹됨), 스트림의 인코딩과 매개변수, 시계와 시간대의 차이, 실행된 단계와 그 결과.
  • 포함되지 않는 내용: 비밀번호, 사용자 이름, 기기에 지정한 이름, 공인 주소나 동적 도메인 이름, 네트워크 어댑터의 하드웨어 주소, 이메일 주소, 토큰 및 그 밖의 식별 정보, 사진과 영상. 긴 일련번호는 마지막 네 글자만 남습니다.
  • 마스킹은 자동으로 이루어지며 가려진 항목마다 표시가 남습니다. 그래도 보내기 전에 보고서를 검토해야 하며 모든 항목을 끌 수 있습니다.
이메일에 포함된 질문

이메일은 이 기능이 실험적이며 보고서를 보내도 지원이 보장되지 않는다는 것을 확인하는 영어 문장으로 시작합니다. 이어서 가장 편한 언어로 작성해 주세요. 개발팀은 어떤 언어든 읽을 수 있습니다.와 아는 범위에서 답해 주세요:가 나오고, 번호가 붙은 질문 6개가 이어집니다. 기기 라벨에 인쇄된 브랜드와 모델, 펌웨어 버전, 기기 종류, 기대한 동작과 실제 동작의 차이, 제조사의 자체 앱이나 미디어 플레이어에서 기기가 표시되는지 여부, 미디어 플레이어에서 열리는 RTSP 주소(사용자 이름, 비밀번호, 주소를 먼저 지운 것)입니다. 그 뒤에 답변을 쓸 공간과 대시 줄이 오고, 이어서 보고서가 나옵니다. 질문에 답변하면 개발자가 기기를 평가하는 데 도움이 됩니다.

저장된 보고서

보고서는 모두 이 기기에 저장되며 최근 5개가 유지됩니다. 추가에 실패하면 상세 정보를 개발자에게 보내기 아래에 저장 날짜가 표시된 항목(예: 2026년 11월 13일 오전 9:41의 이전 보고서)이 나타나며, 이를 탭하면 가장 최근에 저장된 보고서가 열립니다. 저장된 보고서는 저장 당시의 내용을 그대로 보여 주며 항목별로 전환할 수 없습니다. 내용을 다시 고르려면 상세 정보를 다시 수집합니다.

저장된 보고서를 삭제하는 방법은 다음과 같습니다.

  1. 보고서 페이지 맨 아래의 저장된 보고서 삭제를 탭합니다.

    확인: 저장된 보고서를 모두 삭제할까요? 대화상자가 표시됩니다. 이 기기에 저장된 모든 기기 보고서가 제거되며 이미 이메일로 보낸 보고서는 영향을 받지 않는다는 설명이 나옵니다.

  2. 대화상자에서 저장된 보고서 삭제를 탭합니다.

    확인: 저장된 보고서가 모두 삭제됩니다. 페이지에 저장된 보고서가 표시되어 있었으면 페이지가 닫힙니다. 새로 수집한 보고서는 화면에 그대로 남으며 다시 저장되지 않습니다.

네트워크 검색으로 기기 찾기

위치: 화면 아래의 도구 탭

기기의 IP 주소를 모를 때는 도구 탭에서 네트워크 범위를 검색할 수 있습니다. 검색은 80, 554, 2020, 8000, 34567, 37777의 여섯 포트를 확인하고 응답한 주소를 나열합니다. 이어서 많은 카메라와 녹화기가 로그인 없이 응답하는 기기 탐색 방식으로, 찾은 기기에 정체를 묻습니다. 포트 확인에서는 찾지 못했지만 이 질문에 응답한 기기도 목록에 추가됩니다.

  1. 화면 아래의 도구 탭을 선택합니다.

    확인: 서브넷 섹션의 이 기기 행에 현재 네트워크 주소와 마스크가 표시됩니다(예: 192.168.1.10/24). 주소 입력란과 범위에는 현재 네트워크가 채워져 있습니다.

  2. 선택 사항: 다른 네트워크를 검색하려면 주소 입력란에 네트워크를 입력하고(예: 192.168.1.0) 범위 메뉴에서 범위를 선택합니다.

    확인: 입력란 아래에 검색할 네트워크와 호스트 수가 한 줄로 표시됩니다(예: 192.168.1.0/24 검색 · 호스트 254개).

  3. 검색을 탭합니다.

    확인: 254대 중 120대 검색됨 진행 상황이 표시되고 버튼이 정지로 바뀝니다.

  4. 검색이 끝날 때까지 기다립니다. 일찍 끝내려면 정지를 탭합니다.

    확인: 찾은 기기에 응답한 주소가 나열되며, 각 행에 해당 주소에서 열려 있는 포트가 배지로 표시됩니다. 기기에 정체를 묻는 동안에는 기기 식별 중…이 표시되고, 그 뒤 기기가 응답한 행에는 이름이나 모델, 브랜드와 모델, 녹화기의 채널 수가 표시되며, 아직 활성화해야 하는 기기에는 활성화되지 않음이 표시됩니다. 찾은 기기가 없으면 아직 기기를 찾지 못했습니다. 문구가 표시됩니다.

  5. 결과에서 행을 탭합니다.

    확인: IP 주소 또는 호스트 이름 입력란에 주소가 이미 입력되고 기기가 알려 준 정보가 반영된 기기 추가 양식이 열립니다. ‘기기 추가 양식’의 단계에 따라 계속 진행합니다.

  • 양식은 주소 외에도 기기가 알려 준 정보를 가져옵니다. 이름이나 모델은 이름으로, 관리 서비스의 포트는 HTTP 포트로, 목록의 브랜드인 경우 채널 수는 카메라로 가져옵니다. 자체 프로토콜을 쓰는 기기 제품군의 기기가 기본값이 아닌 포트를 사용하면 해당 연결 방식과 그 기기 포트가 선택되고 고급이 펼쳐집니다.
  • 검색에서 기기가 활성화되지 않은 것으로 확인되면 양식 맨 위에 먼저 활성화해야 한다는 안내가 표시됩니다. 자세한 내용은 ‘새 기기 활성화’ 참조.
  • 범위에서는 /26, /25, /24, /23, /22, /16을 각각 네트워크 마스크와 함께 제공하며(예: /24, 255.255.255.0), 현재 네트워크의 접두사가 이 중 어느 것도 아니면 그 접두사도 제공합니다. 범위에 주소가 1,024개를 넘으면 모든 주소를 확인하지 않고 균등하게 표본을 추출하여 검색하며, 입력란 아래 줄에 예를 들어 10.0.0.0/16 검색 · 65534개 중 1024개 표본이 표시됩니다.
  • 주소 입력란이나 범위가 현재 네트워크와 다르면 내 서브넷 사용이 나타나며, 이를 탭하면 현재 네트워크로 되돌아갑니다.
  • 주소 입력란의 형식이 올바르지 않으면 192.168.1 또는 192.168.1.0 같은 서브넷을 입력하세요. 문구가 표시됩니다.
  • 기기를 추가한 뒤에는 기기 목록이 아니라 도구 탭으로 돌아갑니다.
검색 결과의 한계

검색은 카메라 포트에서 응답하거나 탐색 요청에 응답하는 기기만 찾습니다. 스스로를 식별하지 않는 기기는 카메라일 수도 녹화기일 수도 있으며, 종류는 기기를 추가할 때 확인됩니다. 열린 포트와 서버 이름은 제조사를 짐작하는 단서가 됩니다.

검색이 끝까지 완료되었는데 결과가 하나도 없으면 카메라가 이 네트워크에 있다면, 개인정보 보호 설정에서 Cam Hub의 로컬 네트워크 기기 검색 권한이 켜져 있는지 확인해 보세요. 문구가 표시됩니다. 로컬 네트워크 권한이 거부된 경우에는 검색에서 오류가 표시되지 않고 결과도 비어 있습니다. 권한이 켜져 있는지 확인합니다: 설정 › 개인정보 보호 및 보안 › 로컬 네트워크 › Cam Hub
