9제어 패널과 웹훅

제어 패널은 LiveView Mix 비디오 월의 타일 하나로, 버튼 한 줄이 들어 있습니다. 각 버튼은 눌렀을 때 원하는 주소로 HTTP 요청을 전송하므로 Home Assistant 웹훅이나 서비스 호출, 릴레이 보드, Node-RED 등 iPhone 또는 iPad에서 접근할 수 있는 모든 HTTP 서비스에 사용할 수 있습니다. 같은 버튼을 Apple Watch에서도 누를 수 있습니다.

제어 패널의 기능

제어 패널은 제목, 여러 개의 버튼, 선택 사항인 시계로 구성됩니다. 각 버튼에는 메서드, URL, 헤더, 본문으로 이루어진 HTTP 요청 하나가 통째로 저장됩니다. 버튼을 누르면 요청이 Cam Hub 서버를 거치지 않고 이 iPhone, iPad 또는 Apple TV에서 해당 주소로 직접 전송됩니다. Apple Watch에서 누른 버튼은 Apple Watch가 직접 보내거나 페어링된 iPhone을 거쳐 보냅니다. 자세한 내용은 ‘Apple Watch의 버튼’ 참조.

  • Cam Hub는 요청을 전송할 뿐입니다. URL과 내용은 전적으로 사용자가 정합니다. Cam Hub는 어떤 서비스가 응답하는지 확인하지 않으며 특정 스마트홈 제품 전용 컨트롤러도 아닙니다.
  • 요청은 비디오 월이나 Apple Watch에서 버튼을 눌렀을 때만 전송됩니다. 배치 화면에서 패널을 탭하면 편집기가 열릴 뿐 아무것도 전송되지 않습니다.
  • 제어 패널은 iPhone과 iPad에서 만들고 편집합니다. Apple TV는 가로 페이지의 패널을 전체 화면 비디오 월에서 표시하고 실행합니다. 자세한 내용은 ‘비디오 월에서의 패널 모습’ 참조. Apple Watch에는 패널의 버튼이 표시됩니다. 자세한 내용은 ‘Apple Watch의 버튼’ 참조.
제어 패널은 카메라 한도를 하나 사용합니다

제어 패널마다 요금제의 카메라 한도를 하나씩, 카메라가 쓰고 남은 한도에서 사용하므로 패널 때문에 카메라가 영상을 잃는 일은 없습니다. 한도가 부족하면 패널이 잠기고 비디오 월과 Apple Watch에서 버튼을 사용할 수 없습니다. 자세한 내용은 ‘요금제 한도가 비디오 월에 미치는 영향’ 및 ‘한도를 사용하는 항목’ 참조.

비디오 월에 제어 패널 추가

사전 조건: LiveView Mix가 설정되어 있고 비디오 월에 카메라가 하나 이상 있어야 합니다. 설정 방법은 ‘카메라 6대로 첫 비디오 월 만들기’ 참조. 설정하지 않은 상태에서도 기기를 추가했다면 설정 › LiveView Mix를 통해 비디오 월 배치에 접근할 수 있습니다. 제어 패널은 가로 페이지, 세로 페이지, iPhone Duo의 어느 캔버스에든 놓을 수 있습니다. 세로 페이지에 놓으려면 2단계 다음에 레이아웃 조정 페이지 맨 위의 전환 스위치에서 세로 페이지를 탭합니다. 이미 선택되어 있으면 이 동작은 필요 없습니다. iPhone Duo의 두 캔버스가 켜져 있는 동안에는 탭의 오른쪽 위에 전체 화면 버튼만 있습니다. 이 경우 2단계 대신 캔버스 오른쪽 위의 슬라이더가 있는 둥근 버튼을 탭한 다음 메뉴에서 레이아웃 조정을 탭합니다. 자세한 내용은 ‘iPhone Duo의 두 캔버스’ 참조. 나머지 단계는 같습니다.

  1. 화면 아래의 LiveView Mix 탭을 선택합니다.

    확인: 미리보기 비디오 월이 표시되고 오른쪽 위에 버튼 3개가 있습니다.

  2. 오른쪽 위 버튼 3개 중 맨 오른쪽인 레이아웃 조정 버튼을 탭합니다.

    확인: 레이아웃 조정 페이지가 열립니다.

  3. 비디오 월 배치를 탭합니다.

    확인: 배치 페이지가 열립니다. 위쪽에 비디오 월의 캔버스가 있고 그 아래의 순서 목록에 채워진 모든 타일이 각각의 번호 아래에 나열됩니다.

  4. 캔버스에서 점선 윤곽과 +로 표시된 사용하지 않는 타일을 탭합니다. 사용하지 않는 타일이 다른 비디오 월 페이지에 있으면 먼저 캔버스 아래의 화살표를 사용하거나 옆으로 쓸어넘깁니다.

    확인: 타일 번호를 제목으로 하는 메뉴(예: 슬롯 9)가 나타납니다.

  5. 이미지, 제어 패널, 시계 또는 레이블…을 탭합니다.

    확인: 타일 편집기가 화면 아래에서 올라오며 슬롯 9라는 제목이 표시됩니다. 첫 번째 행은 표시 내용이고 현재 값은 빈 슬롯입니다.

  6. 표시 내용을 탭하고 메뉴에서 제어를 선택합니다.

    확인: 페이지에 템플릿, 패널, 버튼의 세 섹션이 표시됩니다. 템플릿은 대문·셔터, 패널 제목은 앱의 언어로 된 대문이며, 버튼 섹션에는 버튼 3개가 있고 각 버튼 아래에 주황색으로 엔드포인트 미설정이 표시됩니다.

  7. 템플릿을 탭하고 가장 가까운 유형을 선택합니다.

    확인: 버튼 섹션이 해당 템플릿의 기본 버튼으로 바뀝니다. 템플릿의 내용은 ‘템플릿’ 참조.

  8. 패널 섹션의 제목 입력란에 패널의 이름을 입력합니다.

    확인: 입력란에 이름이 표시되며, 이 이름은 나중에 패널의 버튼 위에 표시됩니다.

  9. 선택 사항: 색상을 탭하고 테두리와 버튼의 색상을 선택합니다.

    확인: 색상 아이콘에 선택한 색상이 표시됩니다. 기본값은 청록색입니다.

  10. 선택 사항: 시각 표시를 켭니다.

    확인: 초, 날짜, 요일, 24시간제의 스위치 4개가 나타납니다. 시계는 버튼 아래 공간에 표시됩니다.

  11. 모든 버튼의 URL과 내용을 ‘버튼 설정’의 설명대로 설정합니다.

    확인: 버튼 섹션의 모든 행에 엔드포인트 미설정 대신 레이블 아래에 URL의 호스트 이름이 표시됩니다.

  12. 타일 편집기 오른쪽 위의 완료를 탭합니다.

    확인: 배치 페이지로 돌아가며 캔버스의 타일에 비디오 월에 표시될 모습 그대로 패널이 표시됩니다.

  13. 배치 페이지 오른쪽 위의 완료를 탭합니다.

    확인: 레이아웃 조정 페이지로 돌아갑니다.

  14. 레이아웃 조정 페이지 오른쪽 위의 완료를 탭합니다.

    확인: LiveView Mix 탭으로 돌아가며 미리보기 비디오 월에 새 제어 패널이 표시됩니다.

  • 레이아웃의 모든 타일이 채워져 있으면 캔버스에 사용하지 않는 타일이 표시되지 않습니다. 먼저 배치 페이지 위쪽의 레이아웃 행에서 타일이 더 많은 레이아웃을 선택하거나 타일 하나를 비웁니다. 자세한 내용은 ‘비디오 월과 타일 배치’ 참조.
  • 다른 페이지에 이미 있는 패널은 다시 만들지 않고 복사할 수 있습니다. 자세한 내용은 ‘세로 페이지’ 참조. 다른 비디오 월 페이지에 있는 패널은 빈 타일로 옮길 수 있습니다. 자세한 내용은 ‘타일을 빈 타일로 옮기기’ 참조.
  • 타일 편집기 왼쪽 위의 취소를 탭하면 버튼에 대한 모든 변경을 포함하여 비디오 월 전체가 편집기를 열었을 때의 상태로 되돌려집니다.
  • 표시 내용을 다른 항목으로 바꾸면 패널의 제목과 모든 버튼이 지워집니다. 패널을 제거하려면 표시 내용을 빈 슬롯으로 설정하거나, 배치 페이지의 순서 목록에서 해당 행을 왼쪽으로 쓸어넘기고 삭제를 탭합니다. 어느 쪽이든 타일이 비워지며 다른 타일은 움직이지 않습니다.
  • 이미지, 시계, 레이블 타일은 ‘타일에 카메라 대신 표시할 수 있는 내용’ 참조.
  • 설정 › LiveView Mix를 통해 비디오 월 배치에 접근해도 이후의 조작은 같습니다.

패널의 설정 항목

항목설명
표시 내용타일의 내용입니다. 빈 슬롯, 이미지, 제어, 시계, 레이블 중에서 선택합니다. 제어를 선택하면 타일이 제어 패널이 됩니다.
템플릿자세한 내용은 ‘템플릿’ 참조.
제목버튼 위에 표시되어 패널이 무엇을 제어하는지 알려 주며, Apple Watch에서는 그룹 제목으로 사용됩니다. 비워 두면 제목이 표시되지 않습니다.
색상패널의 테두리와 버튼의 색상이며, Apple Watch의 아이콘에도 사용됩니다.
시각 표시버튼 아래 공간에 현재 시각을 표시합니다. 켜면 초, 날짜, 요일, 24시간제를 선택할 수 있습니다. 시각 표시와 스위치 4개는 기본적으로 꺼져 있습니다. 24시간제가 꺼져 있으면 시각은 앱 언어의 관례를 따릅니다. 요일과 월의 이름은 앱의 언어를 따릅니다. 이 기본값은 시계 타일의 기본값과 다릅니다. 자세한 내용은 ‘타일에 카메라 대신 표시할 수 있는 내용’ 참조.
버튼버튼 목록입니다. 행을 탭하면 해당 버튼을 편집하고, 행을 왼쪽으로 쓸어넘기면 삭제하며, 버튼 추가를 탭하면 맨 끝에 빈 버튼을 추가합니다. 목록의 순서는 바꿀 수 없으며, 순서를 바꾸려면 버튼을 삭제하고 다시 추가합니다. 각 행에는 아이콘, 레이블, URL의 호스트 이름이 표시되며, 올바른 URL을 입력하지 않은 동안에는 대신 주황색으로 엔드포인트 미설정이 표시됩니다. 레이블이 비어 있으면 행에 버튼이 표시됩니다.

버튼 설정

사전 조건: ‘비디오 월에 제어 패널 추가’의 설명대로 타일 편집기가 열려 있고 제어가 선택되어 있어야 합니다.

  1. 버튼 섹션에서 설정할 버튼을 탭합니다. 새 버튼을 만들려면 먼저 버튼 추가를 탭한 다음 새 행을 탭합니다.

    확인: 해당 버튼의 편집기가 표시됩니다. 제목은 버튼의 레이블이며, 새 버튼처럼 레이블이 비어 있는 동안에는 버튼입니다. 왼쪽 위에는 뒤로 화살표만 있습니다.

  2. 아이콘 행 아래의 아이콘 줄에서 사용할 아이콘을 탭하거나 오른쪽 입력란에 SF Symbols 아이콘의 이름을 입력합니다.

    확인: 아이콘 행에 선택한 아이콘과 그 이름(예: arrow.up.to.line)이 표시됩니다.

  3. 레이블 입력란에 아이콘 아래에 표시할 텍스트를 입력합니다.

    확인: 입력란에 텍스트가 표시됩니다. 페이지 제목도 같은 텍스트로 바뀝니다.

  4. 실행하기 전에 확인이 필요한 버튼은 실행 전 확인을 켭니다.

    확인: 스위치가 켜집니다. 이제 비디오 월과 Apple Watch에서 버튼을 누르면 확인 상자가 나타납니다. 자세한 내용은 ‘버튼을 누르고 결과 확인하기’ 참조.

  5. 요청 섹션의 메서드 메뉴에서 GET, POST, PUT, DELETE 중 하나를 선택합니다.

    확인: 메뉴에 선택한 메서드가 표시됩니다. GET이면 페이지 아래쪽에 본문 섹션이 없고 나머지 세 메서드에서는 표시됩니다.

  6. 메서드 아래 입력란에 http:// 또는 https://로 시작하는 전체 URL을 입력합니다.

    확인: 입력란에 URL이 표시됩니다.

  7. iPhone에서 선택 사항: Apple Watch 섹션에서 전송 방식을 탭하고 자동, Apple Watch에서 직접, iPhone 경유 중 하나를 선택합니다.

    확인: 메뉴에 선택한 항목이 표시되고, 그 아래의 안내문에 그 항목의 동작이 설명됩니다. 각 항목의 의미는 ‘Apple Watch의 버튼’ 참조.

  8. 헤더가 필요하면 헤더 추가를 탭하고 이름과 값 입력란에 헤더의 이름과 값을 입력합니다.

    확인: 헤더 섹션에 행이 추가되고 두 입력란에 입력한 텍스트가 표시됩니다. 헤더가 더 필요하면 이 단계를 반복합니다. 헤더를 삭제하려면 행을 왼쪽으로 쓸어넘깁니다.

  9. 내용을 전송해야 하면 본문 섹션 위쪽 입력란에서 콘텐츠 유형(기본값은 application/json)을 확인한 다음 그 아래 텍스트 상자에 내용을 입력합니다.

    확인: 텍스트 상자에 내용이 표시됩니다. 내용은 입력한 그대로 전송됩니다.

  10. 왼쪽 위의 뒤로 화살표를 탭합니다.

    확인: 타일 편집기로 돌아가며 버튼의 행에 레이블 아래 URL의 호스트 이름이 표시됩니다.

입력란설명
아이콘행 아래의 흔히 쓰는 아이콘 20개를 바로 탭할 수 있습니다. 모든 SF Symbols 아이콘의 이름을 직접 입력할 수도 있으며, 이름은 정확하게 입력해야 합니다. 이름이 SF Symbols 이름이 아니거나 입력란이 비어 있으면 비디오 월과 Apple Watch에서 버튼에 아이콘이 표시되지 않습니다. 입력란이 비어 있으면 편집기에는 물음표가, 버튼 목록의 행에는 번개 모양이 표시됩니다.
레이블아이콘 아래에 표시되며 확인 상자의 빨간색 버튼 텍스트로도 사용됩니다. 레이블이 비어 있으면 버튼에는 아이콘만 표시되고 확인 상자의 빨간색 버튼에는 확인이 표시됩니다.
실행 전 확인켜면 버튼을 눌렀을 때 먼저 확인 상자가 열립니다. 문 열기, 잠금 해제, 경보처럼 실제 장비를 움직이는 버튼은 켜 두어야 합니다.
메서드GET, POST, PUT, DELETE 중 하나이며 기본값은 POST입니다. GET은 본문을 전송하지 않습니다.
URLhttp:// 또는 https://로 시작해야 하며 호스트 이름이나 주소가 있어야 합니다. 앞뒤의 공백은 무시됩니다. 쿼리 매개변수는 URL 안에 직접 씁니다. URL이 비어 있거나 형식이 올바르지 않으면 버튼을 눌렀을 때 실패가 표시되며, 그 버튼은 Apple Watch에 나타나지 않습니다.
전송 방식iPhone에서만 Apple Watch 섹션에 표시됩니다. Apple Watch에서 누른 버튼을 Apple Watch가 직접 보낼지 iPhone을 거쳐 보낼지 정하며, 기본값은 자동입니다. 자세한 내용은 ‘Apple Watch의 버튼’ 참조.
헤더이름과 값을 원하는 만큼 입력할 수 있습니다. 이름이 비어 있는 행은 건너뜁니다. 여기에 입력한 Content-Type 헤더는 본문 섹션의 콘텐츠 유형 입력란보다 우선합니다.
본문POST, PUT, DELETE에서만 표시됩니다. 위쪽 입력란은 콘텐츠 유형이며 기본값은 application/json이고, 그 아래 텍스트 상자가 내용입니다. 내용이 비어 있으면 본문을 전송하지 않습니다. 콘텐츠 유형 입력란의 값은 내용이 비어 있지 않고 Content-Type 헤더를 입력하지 않았을 때만 첨부됩니다.

버튼을 누르고 결과 확인하기

버튼은 LiveView Mix 탭의 미리보기 비디오 월과 전체 화면 비디오 월에서 누를 수 있습니다. Apple TV에서는 전체 화면 비디오 월에서만 버튼을 누를 수 있습니다. 새로 설정한 버튼에는 별도의 테스트 기능이 없으며, 한 번 눌러 보고 수신 측에서 요청이 도착했는지 확인하는 것이 테스트입니다.

  1. 미리보기 비디오 월 또는 전체 화면 비디오 월에서 패널의 버튼을 탭합니다.

    확인: 실행 전 확인이 꺼진 버튼은 즉시 아이콘이 로딩 표시로 바뀌며, 이는 요청이 전송되었다는 뜻입니다. 이 설정이 켜진 버튼은 패널 옆에 확인 상자가 열립니다.

  2. 확인 상자가 나타나면 상자 안에서 누른 버튼의 레이블이 적힌 빨간색 버튼을 탭합니다. 취소하려면 상자 바깥 아무 곳이나 탭합니다.

    확인: 상자가 닫히고 아이콘이 로딩 표시로 바뀝니다. 취소하면 요청이 전송되지 않습니다.

  3. 버튼의 아이콘을 지켜봅니다.

    확인: 결과에 따라 아이콘이 녹색 체크 표시 또는 주황색 경고 삼각형으로 바뀌었다가 약 1.6초 뒤에 원래 아이콘으로 돌아옵니다.

버튼의 표시의미
설정한 아이콘대기 상태이거나 결과 표시가 끝났습니다.
로딩 표시요청을 전송했고 응답을 기다리는 중입니다. 10초 안에 응답이 오지 않으면 요청은 실패한 것으로 처리됩니다.
녹색 체크 표시수신 측이 200에서 299 사이의 상태 코드로 응답했습니다. 리디렉션은 자동으로 따라가며 최종 응답으로 판단합니다.
주황색 경고 삼각형요청이 성공하지 못했습니다. 원인은 URL이 비어 있거나 형식이 올바르지 않음, 연결 없음, 시간 초과, 신뢰할 수 없는 인증서, 200에서 299를 벗어난 상태 코드(예: 401, 404, 500) 등일 수 있습니다. 화면에는 원인이 표시되지 않으며 기록도 남지 않습니다.
  • 녹색 체크 표시는 수신 측이 성공적으로 응답했다는 뜻일 뿐, 장비가 실제로 움직였다는 증거는 아닙니다. 결과를 확인하려면 수신 측의 기록을 봅니다.
  • 누를 때마다 요청이 하나씩 전송되며 반복해서 누르는 것을 막는 장치는 없습니다. 연속으로 두 번 누르면 요청이 두 번 전송됩니다. 실제 장비를 움직이는 버튼은 실행 전 확인을 켜 두어야 합니다.
  • 주황색 삼각형이 반복해서 나타나면 다음 순서로 확인합니다. URL이 올바른지, iPhone 또는 iPad와 수신 측이 같은 네트워크에 있거나 서로 접근할 수 있는지, 수신 측의 주소를 해석할 수 있는지 확인합니다. 수신 측이 로컬 네트워크에 있으면 Cam Hub에 로컬 네트워크 접근이 허용되어 있어야 합니다. 자세한 내용은 ‘네트워크 검색으로 기기 찾기’ 참조. 그 밖의 문제는 15장 ‘문제 해결’ 참조.
  • Apple Watch에서 버튼을 누르는 방법은 ‘Apple Watch의 버튼’ 참조.

비디오 월에서의 패널 모습

  • 버튼 배치: 버튼 1개는 1열, 2개는 2열, 3개는 3열, 4개는 2 × 2, 5개 이상은 3열로 배치됩니다.
  • 작은 타일: 패널이 자동으로 줄어듭니다. 시계가 가장 먼저 숨겨지고 그다음 아이콘 아래의 레이블이 숨겨지며, 제목과 아이콘은 남습니다.
  • 요금제: 제어 패널마다 카메라가 쓰고 남은 한도에서 카메라 한도를 하나씩 사용합니다. 한도를 넘는 패널에는 자물쇠, 제목, 요금제에 포함되지 않음이 표시되고(작은 타일에는 자물쇠와 제목만, 또는 자물쇠만 표시됩니다) 버튼을 사용할 수 없으며, 미리보기에서는 타일에 자물쇠와 요금제에 포함되지 않음이 표시됩니다. 각 비디오 월의 패널은 각각 따로 계산됩니다. 가로 페이지는 항상, 세로 페이지는 켜져 있는 동안, iPhone Duo의 아래쪽 캔버스는 두 캔버스가 켜져 있는 동안 계산되며, 복사한 패널은 원본과 따로 계산됩니다. 시계, 레이블, 이미지, 빈 타일은 한도를 사용하지 않습니다. 무료 버전에서는 독립형 카메라, 녹화기 채널, 제어 패널이 같은 2자리를 함께 쓰며 제어 패널이 마지막 순서입니다. 구독을 하나라도 하면 이 공동 한도가 없어집니다. NVR 요금제만 구독한 경우 제어 패널은 녹화기 채널 수와 상관없이, 활성화된 독립형 카메라가 카메라 한도 2개 중 쓰고 남은 자리를 사용합니다. 카메라 한도를 2개보다 늘리는 것은 카메라 요금제뿐입니다. 계산 규칙은 ‘요금제 한도가 비디오 월에 미치는 영향’ 및 ‘한도를 사용하는 항목’ 참조.
  • Apple TV: 패널은 iPhone이나 iPad에서 만듭니다. Apple TV는 가로 페이지의 패널을 전체 화면 비디오 월에서만 표시하며, LiveView Mix 탭의 미리보기에는 카메라만 표시됩니다. 비디오 월에 Apple TV에 있는 카메라가 하나도 없으면(예: 제어 패널만 있는 경우) 탭에 전체 화면으로 열기와 LiveView Mix 패널은 전체 화면 비디오 월에 표시됩니다. 안내가 표시됩니다. 전체 화면을 선택하면 비디오 월이 열립니다. 버튼을 누르려면 리모컨으로 선택을 버튼으로 옮긴 다음 선택 버튼을 누릅니다. 버튼은 하나하나가 따로 선택됩니다. 실행 전 확인이 켜진 버튼은 버튼의 레이블(레이블이 비어 있으면 확인)과 취소가 있는 확인 대화상자를 엽니다. 잠긴 패널은 선택이 건너뜁니다. Apple TV에서는 패널이 축소되지 않으므로 시계와 레이블이 항상 표시됩니다. 자세한 내용은 ‘LiveView Mix 탭’ 참조.
  • Apple Watch: 요금제에 포함된 모든 패널의 버튼이 페어링된 Apple Watch에 나타납니다. 자세한 내용은 ‘Apple Watch의 버튼’ 참조.
  • 백업과 공유: 헤더 값을 포함한 패널의 설정은 앱 설정에 속합니다. 모든 iCloud 백업에 포함되며, 내보낼 때 앱 설정 포함이 켜져 있으면 공유 코드에도 포함됩니다. 자세한 내용은 10장 ‘공유와 백업’ 참조.

Apple Watch의 버튼

Apple Watch의 Cam Hub는 페어링된 iPhone에 설정된 제어 패널의 버튼을 표시하며, 한 번 탭하면 버튼을 실행합니다. 그 밖에는 아무것도 표시하지 않으며 영상도 카메라도 없습니다. Apple Watch 앱에는 자체 설정, 로그인, 구매가 없으며, 어떤 버튼을 표시할지는 iPhone이 정합니다.

  • 표시되는 버튼: 요금제에 포함된 모든 제어 패널의 버튼 중 URL이 올바른 버튼이 모두 표시됩니다. 대상은 가로 페이지, 켜져 있는 동안의 세로 페이지, 두 캔버스가 켜져 있는 동안의 iPhone Duo 아래쪽 캔버스입니다. 세로 페이지의 버튼이 가로 페이지의 버튼과 같으면(패널 제목, 레이블, 요청이 같은 경우) 한 번만 나열됩니다.
  • 목록: 화면 제목은 제어입니다. 버튼은 패널 제목 아래에 비디오 월의 순서대로 묶여 있습니다. 각 행에는 패널 색상의 아이콘과 버튼의 레이블(레이블이 비어 있으면 URL)이 표시됩니다. 제목이 같은 패널은 하나의 제목 아래에 함께 나열되며, 제목이 없는 패널의 버튼은 제목 없이 함께 나열됩니다. 패널을 서로 구분하려면 패널마다 고유한 제목을 지정합니다.
  • 동기화: iPhone에서 Cam Hub가 열려 있는 동안에는 패널이나 버튼을 변경하거나 요금제가 바뀔 때마다 iPhone이 Apple Watch에 새 목록을 보냅니다. 구독 종료처럼 앱이 닫혀 있는 동안 일어난 변경은 다음에 iPhone에서 Cam Hub를 열 때나 iPhone을 거치는 다음 누름 때 Apple Watch에 전달되며, 그때까지 Apple Watch가 직접 보내는 버튼은 계속 작동합니다. 요금제에 더 이상 포함되지 않는 패널은 Apple Watch에서 사라집니다.
  • 단독 작동: 목록은 Apple Watch에 저장됩니다. iPhone 앱이 실행 중이 아니거나 iPhone이 연결 범위 밖에 있어도 Apple Watch 앱이 열리고 목록을 표시하며, Apple Watch가 직접 보낼 수 있는 버튼은 그때도 작동합니다.
  • 언어: Apple Watch는 텍스트와 패널의 기본 단어를 Apple Watch의 언어가 아니라 iPhone 앱의 언어로 표시합니다.
  • 버튼이 없는 경우: iPhone에서 받은 목록에 버튼이 하나도 없으면 Apple Watch에 아직 버튼이 없습니다와 iPhone의 LiveView Mix에 제어 패널을 추가하면 패널의 버튼이 여기에 표시됩니다.가 표시됩니다. 첫 목록이 도착하기 전, URL이 올바른 버튼이 있는 제어 패널이 없을 때, 패널이 꺼져 있는 페이지나 캔버스에만 있을 때, 요금제가 어느 패널도 포함하지 않을 때가 해당됩니다.

버튼을 누른 요청의 전송 방식

각 버튼에는 iPhone의 버튼 편집기에 있는 전송 방식에서 고르는 고유의 선택 항목이 있습니다(‘버튼 설정’ 참조).

선택 항목버튼을 눌렀을 때의 동작
자동(기본값)공인 주소이면 Apple Watch에서 바로 보냅니다. 홈 네트워크나 VPN의 주소(예: 192.168.x.x 또는 .local로 끝나는 이름)는 그 주소에 연결할 수 있는 iPhone을 먼저 거칩니다.
Apple Watch에서 직접Apple Watch가 자체 Wi-Fi나 셀룰러 연결, 또는 iPhone의 연결을 통해 항상 직접 요청을 보냅니다. 가장 빠른 방법이지만 홈 네트워크나 VPN의 주소에는 Apple Watch가 연결하지 못할 수 있습니다.
iPhone 경유iPhone의 VPN을 통해서만 연결할 수 있는 서버에, 특히 주소가 공인 주소처럼 보일 때 사용합니다. Apple Watch에는 자체 VPN이 없습니다. Apple Watch는 iPhone이 연결 범위 밖에 있을 때만 직접 요청을 보냅니다.
  • iPhone을 거쳐 보낼 때 Apple Watch는 먼저 iPhone이 응답하는지 최대 약 6초 동안 확인하며, 이를 위해 iPhone 앱이 백그라운드에서 시작될 수 있습니다. 이어서 iPhone은 요금제에 패널이 아직 포함되는지 확인한 뒤 비디오 월과 같은 방식으로 요청을 보냅니다.
  • iPhone이 이 확인에 응답하지 않으면 Apple Watch가 직접 요청을 보냅니다. iPhone이 요청을 받았지만 그 응답이 유실된 경우에는 실패로 표시되며 다시 보내지 않으므로, 스위치가 두 번 전환되는 일은 없습니다.
  • Apple Watch가 직접 보냈다가 실패한 요청은 iPhone을 거쳐 다시 보내지 않습니다. Apple Watch에서 홈 네트워크 주소로 보내는 요청은 Apple Watch가 같은 Wi-Fi 네트워크에 있는 동안에만 작동합니다.

Apple Watch에서 버튼 누르기

사전 조건: iPhone과 페어링된 Apple Watch에 Cam Hub가 설치되어 있고, URL이 올바른 제어 패널이 비디오 월에 하나 이상 있어야 합니다.

  1. Apple Watch에서 Cam Hub를 엽니다.

    확인: Apple Watch에 제어와 패널별로 묶인 버튼이 표시됩니다.

  2. 버튼을 탭합니다.

    확인: 실행 전 확인이 꺼진 버튼은 즉시 행 끝에 로딩 표시가 나타납니다. 이 설정이 켜진 버튼은 이 동작을 실행할까요?라고 묻고, 그 아래에 패널 제목, 버튼의 레이블이 적힌 빨간색 버튼, 취소가 표시됩니다. 패널에 제목이 없으면 질문 아래에 대신 버튼의 레이블이 표시되고, 레이블이 비어 있으면 빨간색 버튼에 확인이 표시됩니다.

  3. 질문이 나타나면 빨간색 버튼을 탭합니다. 취소하려면 취소를 탭합니다.

    확인: 질문이 닫히고 행에 로딩 표시가 나타납니다. 취소하면 아무것도 전송되지 않습니다.

  4. 행의 끝을 지켜봅니다.

    확인: 녹색 체크 표시는 엔드포인트가 성공적으로 응답했다는 뜻이고, 빨간색 경고 삼각형은 요청이 성공하지 못했다는 뜻입니다. Apple Watch가 손목을 가볍게 두드리며, 약 2.5초 뒤에 행이 원래대로 돌아갑니다.

아직 전송 중인 버튼을 다시 탭하면 무시되므로, 성급하게 두 번 탭해도 요청이 두 번 전송되지 않습니다. 비디오 월에서와 마찬가지로 녹색 체크 표시는 수신 측이 응답했다는 뜻일 뿐, 장비가 실제로 움직였다는 증거는 아닙니다.

Home Assistant 사용

다음 두 가지 방법은 Home Assistant를 예로 듭니다. 주소 homeassistant.local, 식별자 gate-open-7f3c9a21, 엔티티 이름 cover.gate는 예시 값이므로 실제 값으로 바꿔야 합니다. Home Assistant 쪽의 동작은 해당 문서에 정의되어 있으며 버전에 따라 달라질 수 있습니다.

사전 조건: Home Assistant가 홈 네트워크에서 실행되고 있고 iPhone 또는 iPad에서 해당 주소에 접근할 수 있어야 하며, LiveView Mix 비디오 월의 타일에 제어가 선택되어 있어야 합니다(‘비디오 월에 제어 패널 추가’ 참조). Home Assistant는 기본적으로 http와 포트 8123을 사용합니다. 앱의 URL 입력란에 있는 예시 텍스트는 https로 시작하므로 실제 환경에 맞게 바꿔야 합니다.

방법 1: 웹훅 트리거(토큰 불필요)

  1. Home Assistant에서 새 자동화를 만듭니다.

    확인: 자동화 편집기가 표시됩니다.

  2. 트리거로 웹훅을 선택하고 추측하기 어려운 식별자(예: gate-open-7f3c9a21)를 입력합니다.

    확인: 편집기에 식별자가 표시됩니다. 식별자는 비밀번호처럼 작동합니다. 식별자와 주소를 아는 사람은 누구나 자동화를 시작할 수 있습니다.

  3. 동작(예: 대문을 여는 엔티티)을 설정하고 자동화를 저장합니다.

    확인: 자동화가 Home Assistant의 자동화 목록에 나타납니다.

  4. Cam Hub에서 ‘버튼 설정’의 1단계에 설명된 대로 사용할 버튼의 편집기를 엽니다.

    확인: 해당 버튼의 편집기가 표시됩니다.

  5. 메서드로 POST를 선택하고 URL 입력란에 http://homeassistant.local:8123/api/webhook/gate-open-7f3c9a21을 입력합니다. 헤더와 본문은 비워 둘 수 있습니다.

    확인: 입력란에 URL이 표시되고, 돌아가면 버튼의 행에 호스트 이름 homeassistant.local이 표시됩니다.

  6. 비디오 월로 돌아가 버튼을 누릅니다.

    확인: 아이콘이 먼저 로딩 표시를 보인 다음 녹색 체크 표시로 바뀝니다.

  7. Home Assistant에서 자동화의 실행 기록을 엽니다.

    확인: 기록에 버튼을 눌러 시작된 실행이 표시됩니다. Home Assistant는 존재하지 않는 식별자에도 성공으로 응답할 수 있으므로 녹색 체크 표시가 아니라 실행 기록으로 판단합니다.

이에 해당하는 요청은 다음과 같습니다.

POST /api/webhook/gate-open-7f3c9a21 HTTP/1.1
Host: homeassistant.local:8123

자동화는 구성 파일로 작성할 수도 있습니다. 다음 예시는 비교용일 뿐이며 구문은 Home Assistant의 버전에 따라 다릅니다.

triggers:
  - trigger: webhook
    webhook_id: gate-open-7f3c9a21
    allowed_methods:
      - POST
    local_only: true
actions:
  - action: cover.open_cover
    target:
      entity_id: cover.gate

웹훅 트리거는 기본적으로 POST와 PUT만 허용하며 로컬 네트워크의 요청만 받습니다. 외부 네트워크에서 사용하려면 별도의 조치가 필요합니다. 자세한 내용은 ‘보안 참고 사항’ 참조. Apple Watch에서 누른 버튼은 전송 방식이 자동 또는 iPhone 경유이면 iPhone을 거쳐 homeassistant.local 같은 주소에 도달합니다. 자세한 내용은 ‘Apple Watch의 버튼’ 참조.

방법 2: 서비스 호출(토큰 필요)

  1. Home Assistant의 프로필 페이지에서 장기 액세스 토큰을 만들고 즉시 복사합니다.

    확인: 토큰이 표시됩니다. 토큰은 보통 만들 때 한 번만 전체가 표시됩니다.

  2. Cam Hub에서 버튼의 편집기를 열고 메서드로 POST를 선택한 다음 URL 입력란에 http://homeassistant.local:8123/api/services/cover/open_cover를 입력합니다.

    확인: 입력란에 URL이 표시됩니다.

  3. 헤더 추가를 탭합니다.

    확인: 헤더 섹션에 이름과 값 입력란 두 개가 있는 행이 추가됩니다.

  4. 이름 입력란에 Authorization을 입력하고 값 입력란에 Bearer, 공백, 복사한 토큰을 차례로 입력합니다.

    확인: 두 입력란에 입력한 텍스트가 표시됩니다. 헤더의 값은 일반 텍스트로 표시됩니다.

  5. 본문 섹션에서 콘텐츠 유형이 application/json인지 확인하고 텍스트 상자에 {"entity_id":"cover.gate"}를 입력합니다.

    확인: 텍스트 상자에 내용이 표시됩니다.

  6. 비디오 월로 돌아가 버튼을 누릅니다.

    확인: 아이콘이 먼저 로딩 표시를 보인 다음 녹색 체크 표시로 바뀝니다. Home Assistant의 기록에 서비스가 호출된 것으로 표시됩니다.

이에 해당하는 요청은 다음과 같습니다.

POST /api/services/cover/open_cover HTTP/1.1
Host: homeassistant.local:8123
Authorization: Bearer <long-lived access token>
Content-Type: application/json

{"entity_id":"cover.gate"}
웹훅 트리거를 우선 사용합니다

웹훅 식별자가 유출되어도 영향은 해당 자동화 하나로 제한됩니다. 장기 액세스 토큰으로는 Home Assistant 전체를 조작할 수 있습니다. 방법 1로 수행할 수 있는 동작에는 방법 1을 사용합니다.

보안 참고 사항

주제설명과 권장 사항
HTTP와 HTTPShttp://로 전송한 요청은 암호화되지 않습니다. 같은 네트워크 경로에 있는 누구나 URL, 헤더의 토큰, 본문을 읽을 수 있습니다. HTTP는 신뢰할 수 있는 홈 네트워크 안에서 민감한 데이터가 없는 웹훅에만 사용합니다. 요청에 토큰이 포함되거나 홈 네트워크를 벗어나는 경우에는 항상 https://를 사용합니다.
HTTPS 인증서Cam Hub에는 자체 서명 인증서를 신뢰하는 옵션이 없습니다. 자체 서명 인증서를 사용하는 https:// 주소는 실패하며 버튼에 주황색 삼각형이 표시됩니다. 로컬 네트워크 안에서는 대신 http://를 사용하거나 iPhone 또는 iPad가 신뢰하는 인증서를 수신 측에 설치할 수 있습니다.
토큰과 식별자의 저장헤더의 값은 편집기에 일반 텍스트로 표시되며 이 기기의 앱 설정에 일반 텍스트로 저장됩니다.
Apple WatchApple Watch로 전달되는 버튼에는 URL, 헤더, 본문을 포함한 요청 전체가 들어 있습니다. 버튼은 페어링된 Apple Watch로 복사되어 저장되므로 헤더의 토큰도 Apple Watch에 저장됩니다.
백업과 공유 코드패널의 설정은 모든 iCloud 백업과, 앱 설정 포함을 켜고 내보낸 모든 공유 코드에 포함됩니다. 이러한 코드는 비밀번호처럼 다루고 PIN이나 비밀번호로 잠급니다. 자세한 내용은 ‘코드 잠금’ 참조. 토큰이 노출되었다면 수신 측에서 폐기하고 새로 만듭니다.
외부 네트워크Home Assistant의 포트 8123을 인터넷에 직접 여는 것은 권장하지 않습니다. 집 밖에서 어떤 방식으로 연결할지(예: VPN 또는 Home Assistant의 공식 원격 접속 방법)는 직접 결정하면 되며, URL은 그에 맞는 주소로 바꿉니다.
물리적 동작문 열기, 잠금 해제, 경보 울리기 버튼에는 실행 전 확인을 켭니다. Cam Hub에는 패널 버튼에 대한 별도의 잠금이 없으므로 잠금이 풀린 기기나 Apple Watch를 조작할 수 있는 사람은 누구나 버튼을 누를 수 있습니다.
이름 확인.local로 끝나는 이름은 일부 네트워크에서 확인되지 않을 수 있습니다. 연결에 실패하면 대신 수신 측의 고정 IP 주소를 입력합니다.
