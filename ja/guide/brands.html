16対応ブランドと接続方法

ブランド名を挙げるのは、この章だけです。デバイス追加フォームの接続方法、各方法でできること、デバイスに必要な条件、デバイスを追加する前にデバイスで準備することを説明します。このマニュアルのほかの部分では、ブランド名を挙げずに機能を説明しています。

接続方法

デバイス追加フォームの詳細 › 接続方法の一覧は、4 つの方法から始まります：自動判別、ONVIF、Xiongmai (XMEye)、RTSP。その下のブランドセクションには 71 のブランドがアルファベット順に並び、検索欄では、そのブランドのカメラが販売されている別の名前でもブランドを探せます。Hikvision、Dahua、Synology は一覧にありません。自動判別が、それぞれ独自のプロトコルで見つけるためです。フォーム自体は「デバイス追加フォーム」で、選び方は「接続方法の選び方」で説明しています。

選択肢Cam Hub の動作適したデバイスアカウント
自動判別（デフォルト） まず、サインインせずに、そのアドレスで開いているポートを確認します。続いて、次の順に試します：メインの Web ポートで認識されたブランド、続いて同じポートで Hikvision のプロトコル、Dahua のプロトコル、Synology Surveillance Station のプログラミングインターフェース。次に、この 3 つのいずれかを別のポートで（たとえば Synology NAS の Web ポート 5000）。次に、ローカルアドレスに限り、ポート 34567 で Xiongmai 独自のプロトコル。次に、応答があった各ポートで ONVIF。最後に、応答があった各 RTSP ポートでプレーンな RTSP（デバイスが明らかにしたブランドのパス、多くのカメラが使うパス、一覧のすべてのブランドのパスの順）。最初に接続できた方法が、そのポートとともに採用されます。Hikvision、Dahua、Synology、Xiongmai でサインインが拒否された場合は、その時点で試行を終了します。ONVIF と RTSP では、2 回目の拒否で終了します。「詳細」で入力したポートが最初に試され、80 と 554 以外の入力したポートが開いている場合は、そのポートだけが使われます。 ほとんどのデバイス：Hikvision、Dahua、Synology のカメラとレコーダー、ローカルネットワーク内の Xiongmai のデバイス、ONVIF 対応のあらゆるデバイス、一般的なパスまたは一覧のブランドのパスで RTSP を提供するカメラ。 デバイスのアカウント。Synology の場合は、Surveillance Station を使用できるネットワークストレージデバイスのアカウント。
ONVIF 検出を省略し、オープンプロトコルの ONVIF だけを、HTTP ポートのポート（HTTPS を使用がオンの場合は HTTPS ポート）で使用します。Cam Hub はサービスを /onvif/device_service で探し、そのアドレスが応答しない場合は /onvif/service と /onvif/device で探します。映像は、デバイスが通知するアドレスから取得します。 ONVIF 対応のあらゆるカメラとレコーダー。また、Hikvision、Dahua、Synology のデバイスを ONVIF で使いたい場合。 デバイスの ONVIF ユーザー。デバイスが ONVIF ユーザー専用の一覧を持つ場合は、その一覧にユーザーが存在する必要があります。
Xiongmai (XMEye) Xiongmai 独自のプロトコル（XMEye / NetSurveillance）を、デバイスのポートのポート（変更または転送していなければ 34567）で使用します。ローカルネットワークの外のアドレスも含め、どのアドレスも受け付けます。そのようなアドレスでは、このプロトコルが映像を暗号化しないこと、多くのデバイスではパスワードの保護も弱いことを、フォームが警告します。 自動判別で見つからない、別のポートを使う、またはローカルネットワークの外から接続する Xiongmai のカメラとレコーダー。 デバイスのアカウント。
RTSP プレーンな RTSP で接続し、多くのカメラが使うパス、または入力したパスを試します。デバイスの制御インターフェースには接続しません。ライブ表示のみです。 ブランドが一覧になく、ONVIF がオフになっている、あらゆるブランドのカメラ。 デバイスのカメラアカウント。
一覧のブランド（「一覧のブランド」を参照） プレーンな RTSP で、メーカーが公開しているストリームパスに接続します。デバイスの制御インターフェースには接続しません。ライブ表示のみです。 ONVIF がオフの場合や動作しない場合の、そのブランドのデバイスと、RTSP しか提供しないそのブランドのレコーダー。 デバイスのカメラアカウント。5 つのブランドでは別のアカウント。

自動判別が出発点です。自動判別が対応していないデバイスです。と報告した場合、または意図的にデバイスを ONVIF で使いたい場合は、次に ONVIF を選びます。Xiongmai (XMEye)は、自動判別で接続できない Xiongmai のデバイス向けの選択肢です。一覧のブランドまたは RTSP は、ONVIF がオフのデバイス向けの最後の選択肢です。映像を暗号化していると報告する Xiongmai のレコーダーは、Xiongmai 独自のプロトコルでは視聴できません。その場合、自動判別は ONVIF に進みます。そのようなレコーダーはONVIFで追加します。開発者は、Hikvision、Dahua、Synology の一部のデバイスでテストしています。特定のモデルがどの方法で動作するかは、ファームウェア、設定、ストリームの形式、アカウントの権限、ネットワークによって異なります。

Apple TV の追加フォームには、接続方法の一覧もブランドセクションもありません。代わりに 2 つのスイッチがあり、一方しかオンにできません。ONVIF で接続はONVIFに相当します。Xiongmai で接続はXiongmai (XMEye)に相当し、HTTP ポートとRTSP ポートをデバイスのポートに置き換え（欄が 80 のままの場合は 34567 が入ります）、HTTPS を使用を取り除き、ローカルネットワーク外のアドレスでは同じオレンジ色の警告を表示します。どちらのスイッチもオフの場合、フォームは自動判別を使います。Apple TV では RTSP と一覧のブランドは選べませんが、自動判別がそれらのストリームパスも試し、そのようなカメラを単体のカメラとして追加します。

  • ライブ表示：ONVIF では、デバイスがストリームのアドレスを通知する必要があります。デバイスがメディアサービスを示さない場合、Cam Hub はそのサービスの一般的なアドレスに問い合わせます。映像は TCP 上の RTSP で取得し、デバイスが TCP を拒否した場合は UDP で取得します。
  • SD と HD：Synology Surveillance Station では選択が非表示になり、SD にはカメラが低解像度ストリームを持つ場合にそれが使われます。Xiongmai では、HD がメインストリーム、SD が追加ストリームです。ONVIF では、デバイスの最大のプロファイルが HD、最小のプロファイルが SD で、プロファイルが 1 つだけの場合は両方に使われます。RTSP と一覧のブランドでは、デバイスが提供している場合、SD には見つかったパスに対応する 2 番目のストリームが使われます。提供していない場合、SD には HD と同じストリームが表示されます。
  • 録画再生：Hikvision では、ストレージを持つカメラが、レコーダーと同様に再生されます。Dahua では、レコーダーのメインストリームが再生され、別の時刻に移動すると、その時点から再生し直します。Synology Surveillance Station と Xiongmai では、録画は選んだ時点からストリーミングされます。ONVIF では、デバイスに、ONVIF が再生用に定義する検索サービスと再生サービスが必要です。ONVIF で接続する一部のレコーダーは、直近約 24 時間の録画しか一覧に示しません。
  • 再生速度：Hikvision、Dahua、ONVIF では、レコーダーが高速再生を拒否することがあり、その場合 Cam Hub は通知を表示します。Synology Surveillance Station と Xiongmai では、ストリーミング再生に速度ボタンはありません。
  • カレンダー：どの日に録画があるかを報告する Hikvision のレコーダーでは、再生日のカレンダーでその日に印が付きます。詳しくは「録画カレンダー」を参照してください。
  • イベントの一覧：録画の一覧の上にある連続録画とイベントの切り替えです。「録画とイベントの一覧」を参照してください。Hikvision では、デバイスがインデックスを保持している場合は検出された人物（人物を検出）と、デバイスがイベントをきっかけに録画した映像（イベント録画）が一覧に表示されます。Synology Surveillance Station では、動き（動きを検出）とアラーム入力（アラーム入力）が表示されます。Dahua と Xiongmai では、デバイスがイベントをきっかけに録画した映像（イベント録画）が表示されます。これらでは、選んだ日またはその前日にそのような録画がある場合にのみ、切り替えが表示されます。ONVIF では、すべての録画が連続録画として扱われるため、イベントの一覧はありません。
  • PTZ：Hikvision では、チャンネルで PTZ がオンになっている必要があります。保存した位置はデバイスが一覧を返す場合に表示され、ホームポジションは常に使用できます。Dahua では、PTZ がそのチャンネルに関連付けられている必要があります。保存した位置は提供されますが、ホームポジションはありません。Synology Surveillance Station では、操作はシステムがカメラについて報告する内容に従います。4 方向と、報告された場合はホームポジションです。Xiongmai では、首振り機能のあるカメラに、方向、ズーム、1 から 16 の番号による保存位置が提供され、ホームポジションはありません。ONVIF では、軸はデバイスが報告する内容に従い、ズームだけのカメラには方向パッドが表示されません。詳しくは「PTZ 操作：カメラを動かす」を参照してください。
  • 照準：映像の点または範囲による位置決めに対応していると報告する Hikvision のカメラで提供されます。
  • スナップショット：Xiongmai では、ライブストリームの最初の完全なフレームから画像を取得します。ONVIF では、デバイスがスナップショットのアドレスを提供する必要があります。
  • クリップの録画：1 台表示で再生される H.264 と H.265 の映像で使用できます。詳しくは「クリップの録画」を参照してください。Synology Surveillance Station では、映像のストリームを取得する権限のないアカウントには代わりに 1 枚ずつの画像（MJPEG）が届き、その画面には録画ボタンがありません。Synology Surveillance Station がファイルとして配信する録画は、ファイル全体が共有されます。
  • 音声：Synology Surveillance Station では、通常のストリーミング経路で再生されるのは G.711 だけです。Xiongmai のデバイスは G.711 を送信します。
  • トーク：G.711 の双方向音声チャンネルを報告する Hikvision の単体カメラで提供されます。レコーダーのチャンネルでは提供されません。詳しくは「双方向のトーク」を参照してください。
  • ディスクの状態：Hikvision は各ディスクの状態を報告し、デバイスが提供する場合は S.M.A.R.T. の詳細も報告します。Dahua は、状態、容量、可能な場合は温度を報告しますが、S.M.A.R.T. の詳細は報告しません。Synology NAS は SNMP で読み取ります。SNMP は、NAS でオンにし、Cam Hub で設定する必要があります。詳しくは「ディスクの状態」を参照してください。
  • チャンネル一覧：Hikvision と Dahua は、レコーダーのチャンネルを名前と信号の状態とともに一覧にし、レコーダーでないデバイスにはチャンネルが 1 つあります。Synology Surveillance Station は、システムのすべてのカメラを、信号の状態とともにチャンネルとして一覧にします。Xiongmai のデバイスは、チャンネル数と、チャンネルに付けられた名前を報告しますが、信号の状態は報告しません。ONVIF は、独立した映像ソースごとに 1 つのチャンネルを一覧にし、信号の状態は報告しません。RTSP と一覧のブランドには一覧がありません。カメラの数（1 から 64）を入力し、すべてのチャンネルがオンラインとして表示されます。
  • HTTPS：デバイスが Web インターフェースで HTTPS を提供している場合に使用でき、デバイスごとにオンにします。「HTTPS でデバイスを追加する」と「保存したデバイスの HTTPS」を参照してください。Xiongmai の独自のプロトコルと通常の RTSP には、HTTPS で保護する Web インターフェースがありません。RTSP の映像は、HTTPS では暗号化されません。

どの方法でも提供されないもの：フォーカスとアイリスの操作、録画の保存や書き出し（ファイルとして届く録画は、全体を共有できます）、クラウドアカウントへのサインイン。

一覧のブランド

ブランドセクションのブランドは、プレーンな RTSP で接続します。ブランドを選ぶと、そのブランド名のセクションが追加され、カメラ欄（1 から 64）とパスの欄が表示されます。1 の場合、デバイスはブランド名の付いたカメラとして追加されます。それより大きい数の場合は、チャンネル CH1 から CHn を持つレコーダーとして追加され、プランではレコーダーとして数えられます。パス欄が空の場合、Cam Hub は公開されているパスを順に試し、デバイスが応答したものを採用します。入力が必要なのは、特定のパスを指定する場合だけです。選択肢の RTSP も、多くのカメラが使うパスで同じように動作します。

  • 別のアカウント：Axis、TP-Link (Tapo / VIGI)、ANNKE、MOBOTIX、2Nは、RTSP を使えるようにする前に、メーカーの Web インターフェースまたはアプリで作成した専用のカメラアカウントまたは ONVIF アカウントが必要です。管理者アカウントでのサインインだけでは拒否される場合があります。

  • 自動判別も同じパスを使う：ほかのどの方法でも接続できない場合、自動判別は一覧のすべてのブランドのパスを自動で試し、カメラを単体のカメラとして追加します。ブランドを手動で選ぶ必要があるのは、主にレコーダーの場合、カメラの数を入力する場合、パスを 1 つに固定する場合です。

要件と制限

項目要件または制限
HTTP と HTTPSCam Hub は、デバイスにプレーンな HTTP で接続し、デバイスで HTTPS をオンにした場合は HTTPS で接続します。Xiongmai のデバイスには、代わりにその独自のプロトコルで接続します。映像は RTSP で取得し、まず TCP を使い、デバイスが TCP を拒否した場合は UDP を使います。映像は HTTPS では暗号化されません。HTTPS では、Cam Hub は、HTTPS をオンにしたときにデバイスが提示した証明書（自己署名証明書を含む）か、そのアドレス向けに公的な認証局が発行した証明書を信頼します。HTTP がオフになっているデバイスや、HTTPS しか受け付けないデバイスは、HTTPS を使用をオンにして追加します。「HTTPS でデバイスを追加する」を参照してください。自動判別は、ネットワークストレージデバイスの HTTP の Web インターフェースをポート 5000 で自動的に見つけます。HTTP ポートにポートを入力するのは、Web インターフェースが別のポートを使う場合だけです。HTTPS を使用をオンにすると、Cam Hub は HTTPS のポート 5001 も自動で見つけます。
ONVIF をオンにするONVIFを選ぶ場合は、デバイスで ONVIF をオンにする必要があります。Cam Hub は、HTTP ポートに入力したポート（HTTPS を使用がオンの場合は HTTPS ポート）の /onvif/device_service、/onvif/service、/onvif/device でサービスを探します。工場出荷時の設定で ONVIF がオフになっているデバイスもあります。
RTSP をオンにする映像は RTSP で取得します。自動判別では、Cam Hub が RTSP ポートを見つけます。それ以外では、RTSP ポートに入力したポート（通常は 554）を使います。ネットワークストレージデバイスは、独自のストリーミングパスを先に使用することがあります。デバイスに RTSP 認証の設定がある場合は、Digest を選択します。
専用の ONVIF ユーザーWeb インターフェースのユーザーとは別の ONVIF ユーザーの一覧を持ち、管理者アカウントでのサインインが ONVIF では使えないデバイスがあります。その一覧にユーザーを作成します。一覧のうち 5 つのブランドは、RTSP を使えるようにするために専用のカメラアカウントまたは ONVIF アカウントが必要です：Axis、TP-Link (Tapo / VIGI)、ANNKE、MOBOTIX、2N。
アカウントの権限アカウントには、ライブ映像を表示する権限が必要で、再生には録画を読み取る権限が必要です。Synology では、アカウントが Surveillance Station を使用できる設定になっている必要があります。Cam Hub には確認コードの入力欄がないため、2 段階認証が必要なアカウントは使用できません。
デバイスの時計ONVIF のサインインには、デバイスのタイムスタンプが含まれます。時計が数分ずれていると、サインインに失敗します。デバイスで、ネットワークタイムなどを使って時刻を設定します。録画の時刻は、レコーダーの時計です。
同じネットワーク、クラウドなしCam Hub はデバイスのアドレスに直接接続し、クラウドの中継はありません。ホームネットワークの外からデバイスに接続するには、インターネットから到達できるアドレスを使うか、VPN を経由する必要があります。メーカーのクラウドアプリ経由でしか動作しないデバイスは追加できず、Cam Hub にはクラウドアカウントへのサインインもありません。
ローカルネットワークの外の Xiongmai自動判別が Xiongmai 独自のプロトコルを使うのは、ローカルアドレスに対してだけです。ポート転送やダイナミック DNS のドメイン名の先にある Xiongmai のデバイスは、Xiongmai (XMEye)で追加します。このプロトコルは映像を暗号化せず、多くのデバイスではパスワードの保護も弱くなっています。外部からどう接続するか（VPN を使うなど）は、ご自身でお決めください。
映像形式Cam Hub は H.264 と H.265 を再生し、端末のハードウェアでデコードします。H.265 のハードウェアに対応しない端末や、デコーダーの上限を超える映像サイズでは、映像が表示されません。MJPEG は、いずれかのファミリーでのライブ表示のフォールバックとしてのみ使われます。
音声聞く場合は、G.711（A-law と µ-law）と AAC-LC が再生され、ほかの形式は無音です。カメラを通したトークは、G.711 の双方向音声を提供する Hikvision の単体カメラでのみ動作します。
ロックされたアカウント何度か間違えると、デバイスがアカウントをロックすることがあり、多くの場合は約 30 分間です。自動判別のポートの確認では、サインインは送信されません。Cam Hub は、ブランド独自のプロトコルで最初にサインインが拒否された時点、または ONVIF や RTSP で 2 回目に拒否された時点で停止し、デバイスレポートも、拒否の後は追加のサインインを送信しません。
デバイスの再追加同じアドレス、ポート、ユーザー名でデバイスを追加すると、2 台目を作成せず、保存済みのデバイスが更新されます。「デバイス追加フォーム」を参照してください。

デバイスの一覧のバッジには、カメラまたはレコーダーと表示されます。レコーダーは、「利用枠を使用するもの」で説明したとおり、プランのレコーダーの上限を 1 つ使用します。Cam Hub は次のように判断します。

方法レコーダーとして数えられる場合

Dahuaモデル名に NVR、DVR、XVR が含まれる場合。それ以外は 1 台のカメラです
Synology Surveillance Station常に。システムのすべてのカメラがチャンネルになります
Xiongmai (XMEye)デバイスが複数のチャンネルを報告する場合、またはデバイスタイプに DVR または NVR が含まれる場合
ONVIFデバイスに独立した映像ソースが複数ある場合。そのため、複数のセンサーを持つカメラがレコーダーとして数えられることがあります

デバイスで準備すること

次のチェックリストは、すべてのブランドに当てはまります。デバイスにない項目は省略できます。

  • デバイスをアクティベートし、管理者パスワードを設定します。新品のデバイスは、どのアプリでもサインインする前にアクティベートが必要です。詳しくは「新しいデバイスのアクティベート」を参照してください。
  • ホームネットワークでデバイスに固定アドレスを割り当てます。デバイス側で設定するか、ルーターで予約します。Cam Hub は入力されたアドレスを保持します。詳しくは「デバイスは追加済みだが、接続できない」を参照してください。
  • 端末とデバイスを同じネットワークに置きます。間にゲストネットワーク、別の VLAN、クライアント分離、VPN があってはいけません。
  • デバイスの HTTP サービスをオンにし、ポート（通常は 80）を控えます。
  • RTSP をオンにし、ポート（通常は 554）を控えます。デバイスに RTSP 認証の選択がある場合は、Digest を選択します。
  • デバイスに設定がある場合は ONVIF をオンにし、デバイスが専用の一覧を持つ場合やブランドが必要とする場合は、専用の ONVIF ユーザーまたはカメラユーザーを作成します。
  • 日付、時刻、タイムゾーンを、ネットワークタイムなどで設定します。
  • 映像を H.264 または H.265 に設定し、解像度は中程度、キーフレームの間隔は 1 秒から 2 秒にします。デバイスにサブストリームがある場合は、SD 用に低解像度のものを使用します。
  • ライブ映像を表示でき、再生では表示したいチャンネルの録画を読み取れるアカウントを使用します。
  • 再生を使う場合は、デバイスが録画していること、ディスクまたはカードが装着されていることを確認します。
  • Synology NAS のディスクの状態を使う場合は、NAS で SNMP をオンにします。
  • デバイス追加フォームで求められるアドレス、ユーザー名、パスワードを控えます。自動判別でデバイスが見つからない場合に備えて、ポートも控えます。
追加できないデバイス

メーカーのクラウドアプリ経由でしか動作しないデバイスや、ローカルネットワークでの接続を提供しないデバイスは、Cam Hub に追加できません。HTTPS しか受け付けないデバイスは、HTTPS を使用をオンにして追加します。「HTTPS でデバイスを追加する」を参照してください。

新しいデバイスのアクティベート

一部のブランド（Hikvision を含む）の新品またはリセットしたデバイスには、まだ管理者パスワードがありません。どのアプリでもサインインする前に、アクティベートが必要です。アクティベートで管理者パスワードを設定します。それまではすべてのサインインが拒否され、デバイスの追加はユーザー名またはパスワードが違います。で失敗します。

ネットワークスキャンで、Hikvision のデバイスがまだアクティベートされていないことがわかる場合があります。

  • デバイスがスキャンの問い合わせに応答し、アクティベートされていないと報告した場合、見つかったデバイスのその行に未アクティベートと表示されます。詳しくは「ネットワークスキャンでデバイスを探す」を参照してください。
  • その行から開いたデバイス追加フォームの先頭には、この Hikvision デバイスはまだアクティベートされていません。先に、Hikvision の SADP ツールまたはデバイス自身のウェブページで管理者パスワードを設定して、アクティベートしてください。という案内が表示されます。
  • スキャンの問い合わせに応答しないデバイスには、アクティベートされているかどうかにかかわらず、このような表示はありません。

デバイスをアクティベートするには：

  1. デバイスの説明書に従い、メーカー独自のツールまたはデバイス自身の Web ページでデバイスをアクティベートし、そこで管理者パスワードを設定します。

    確認：デバイスの Web ページなどで、管理者アカウントと新しいパスワードでサインインできるようになります。

  2. Cam Hub のデバイス追加フォームで、管理者アカウント（通常は admin）と新しいパスワードを入力し、追加をタップします。

    確認：フォームが閉じ、デバイスの一覧にデバイスが表示されます。

それでも追加できない場合は、「追加に失敗したとき：チェックリスト」を参照してください。
