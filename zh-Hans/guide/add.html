3添加设备

添加摄像头或录像机需要设备的地址和账号。Cam Hub 会自行判断如何连接设备；也可以改为在“高级”下选择连接方式和端口。

添加设备表单

路径：设备 › ＋ › 添加设备

输入项说明默认值
名称（可选）设备在 Cam Hub 中显示的名称。留空时使用设备报告的型号。通过自动检测以普通 RTSP 连接、但未识别出品牌的摄像头，以其地址命名。在高级下选择 RTSP 添加的设备命名为 RTSP，通过列表中的品牌添加的设备以该品牌命名。空
IP 地址或主机名必填。设备的网络地址。空
用户名必填。设备的登录账号。该输入框为空时，添加不可用。admin
密码设备的登录密码。密码保存在 iPhone 或 iPad 的钥匙串中。空
高级 › 连接方式自动检测、ONVIF、RTSP、某一设备系列的自有协议，或列表中的品牌。如何选择，参见“选择连接方式”。自动检测
高级 › HTTP 端口设备控制接口的端口。使用自动检测时，Cam Hub 会自行查找开放的端口，并优先尝试此处输入的端口。使用 ONVIF 时，此处必须填写设备的 ONVIF 服务端口，例如部分设备使用 2020 或 8899。开启使用 HTTPS后，改为通过 HTTPS 端口访问设备；此处的端口会保留，以备之后关闭 HTTPS 时使用。80
高级 › RTSP 端口视频流的端口。自动检测会优先尝试此处输入的端口。选择 RTSP 端口不是 554 的品牌时，只要此处仍是原来的默认值，就会自动填入该品牌的端口。554
高级 › 使用 HTTPS选择自动检测和 ONVIF 时提供。仅当设备的网页使用 HTTPS 时才开启：开启后，Cam Hub 会在不登录的情况下查找该地址上的 HTTPS，通过 HTTPS 添加设备，并信任设备此时出示的证书。参见“通过 HTTPS 添加设备”。关
高级 › HTTPS 端口开启使用 HTTPS后显示。保持 443 时，Cam Hub 还会在 5001 和 8443 上查找；填写其他端口时，只使用该端口。443
高级 › 设备端口选择某一设备系列的自有协议时，取代上面两个端口显示：设备以该协议响应的端口。34567

  1. 点击屏幕底部的设备标签页。

    确认：屏幕显示设备列表。

  2. 点击右上角的 ＋ 按钮。列表为空时，屏幕中央的添加设备按钮会直接打开表单。

    确认：弹出菜单，其中有添加设备。

  3. 选择添加设备。

    确认：屏幕显示添加设备表单，包含设备和凭据部分，以及折叠的高级部分。

  4. 可选：在名称（可选）输入框中输入设备的名称。

    确认：输入框显示该名称，之后设备列表中会使用这个名称。

  5. 在 IP 地址或主机名输入框中输入设备的地址，例如 192.168.1.64。

    确认：右上角的添加按钮变为可用。

  6. 在用户名和密码输入框中输入设备账号。

    确认：两个输入框均已填写。密码以圆点遮蔽显示。

  7. 点击右上角的添加。

    确认：表单显示正在连接设备…，其下方显示当前步骤，例如正在查找开放的端口…或正在尝试 ONVIF（端口 8899）…。连接成功后，表单自动关闭，新设备出现在设备列表中。

连接过程中，进度指示器取代添加按钮，也无法通过向下滑动关闭表单。点击取消可停止尝试，不会保存任何内容。连接成功后，Cam Hub 会识别设备是录像机还是单个摄像头，读取通道列表并保存设备。

新设备是 Cam Hub 能够通过 SNMP 读取其磁盘的网络存储设备（NAS）时，接着会出现 SNMP 设置面板。这一步是可选的：点击以后再说可关闭面板，之后也可在磁盘健康页面上设置 SNMP，参见“磁盘健康”。无论哪种情况，设备都会保存。

只有套餐额度范围内的通道会被启用。报告有信号的通道优先获得额度，其次是没有信号的通道，两组各按设备中的顺序排列；其余通道显示为已停用。参见“套餐上限与启用通道”。已达到套餐允许的录像机数量时，会打开套餐页面。示例设备占用了免费版的录像机名额时，该页面会说明这一点；删除示例设备即可释放名额。各项额度参见第 11 章“套餐与额度”。

已保存设备的地址无法编辑

已保存的设备可以重命名，其用户名和密码可用编辑凭据更改，参见“更改设备的用户名和密码”。设备的地址无法更改。IP 地址更改后，新地址会被视为另一台设备，如果是录像机，还会占用录像机额度。此时应先删除旧设备（参见第 4 章“设备标签页与通道”），再添加新地址。用相同的地址、端口和用户名再次添加设备时，会就地更新已保存的设备，而不会创建第二台设备。其现有通道保留各自的开关状态。在名称（可选）中输入的名称会替换已保存的名称；该输入框为空时，保留已保存的名称。输入的密码会替换已保存的密码。开启使用 HTTPS时，已保存的设备会开启 HTTPS；未开启时，设备的 HTTPS 设置保持不变。

不选择品牌直接添加

使用默认的自动检测时，Cam Hub 只需要地址和账号。添加过程分为两个阶段：

  1. 端口检查。Cam Hub 检查该地址上摄像头和录像机的常用端口中哪些是开放的：网页和控制接口的端口、ONVIF、RTSP，以及某一设备系列的自有协议。检查时不发送用户名和密码，因此不会计入账号锁定的次数。没有任何响应时，会延长等待时间再检查一次。
  2. 连接尝试。随后 Cam Hub 在有响应的端口上依次尝试各种连接方式，顺序为：内置的厂商协议、某一设备系列的自有协议、ONVIF，最后是普通 RTSP。对于 RTSP，它先尝试设备透露的品牌的视频流路径，再尝试大多数摄像头使用的路径，最后尝试列表中每个品牌的路径。第一种连接成功的方式会被保留，连同连接成功的端口。
  • 在高级下输入的端口会被优先尝试。与默认值（80 或 554）不同且开放的端口会被单独使用，因为在转发多台设备的地址上，其他端口可能属于另一台设备。
  • 为保护账号，厂商协议拒绝登录时，尝试会立即结束并显示用户名或密码错误。ONVIF 和 RTSP 可能使用各自的账号，因此在第二次登录被拒绝后才结束尝试。登录被拒绝后，视频流路径改为逐个尝试。
  • 只能通过 RTSP 访问的摄像头总是作为单个摄像头添加。要添加只提供 RTSP 的录像机，请选择其品牌并输入摄像头数量，参见“选择连接方式”。
  • 某一设备系列的自有协议只在本地网络中的地址上、并且只在其默认端口上自动尝试。对于位于本地网络之外或使用其他端口的这类设备，请在高级下选择其连接方式，参见“连接方式”。
  • 尝试许多视频流路径需要时间。对于不响应错误路径的摄像头，添加可能需要一分钟以上才会成功或失败。
  • 添加失败时，错误信息下方会列出找到的开放端口，例如找到的开放端口：80, 554，或者表单显示这个地址没有找到任何开放的端口。前者表示设备有响应但无法连接；后者表示完全没有任何响应。

自动检测能识别的品牌以及尝试的确切顺序，参见“连接方式”。

选择连接方式

自动检测适用于大多数设备。它无法找到设备，或需要使用特定协议时，请在高级下选择连接方式。

  1. 在添加设备表单中，点击高级。

    确认：该部分展开，显示连接方式、HTTP 端口、RTSP 端口以及使用 HTTPS开关。

  2. 点击连接方式。

    确认：打开带有搜索框的连接方式列表。顶部是自动检测、ONVIF、某一设备系列的自有协议和 RTSP；其下的品牌按字母顺序列出受支持的品牌。

  3. 可选：在搜索框中输入品牌名称的一部分。

    确认：列表只显示匹配的选项。品牌也可以通过其摄像头销售时使用的其他名称找到。

  4. 点击连接方式。

    确认：表单在连接方式一行显示所选方式，并在该部分下方显示说明。选择列表中的品牌或 RTSP 时，会增加一个包含摄像头和路径输入框的部分；选择某一设备系列的自有协议时，两个端口会被设备端口取代。只有选择自动检测和 ONVIF 时才提供使用 HTTPS。

  5. 设备不使用默认端口时，修改端口输入框。

    确认：输入框显示设备实际使用的端口。

可选的连接方式：

  • 自动检测（默认）：由 Cam Hub 自行查找端口和协议，如“不选择品牌直接添加”所述。
  • ONVIF：跳过检测，只在 HTTP 端口中的端口上使用开放的 ONVIF 协议（开启使用 HTTPS时改为在 HTTPS 端口上，参见“通过 HTTPS 添加设备”）。适用于自动检测找不到的摄像头，或需要在同时支持自有协议的设备上使用 ONVIF 的情况。设备上必须开启 ONVIF；设备有单独的 ONVIF 用户列表时，须在其中创建用户。录像回放和 PTZ 控制是否可用，取决于设备提供的功能。
  • RTSP：通过普通 RTSP 连接任何品牌的摄像头，并尝试大多数摄像头使用的视频流路径。这些路径都无效时，请输入摄像头说明书或网页上给出的路径。
  • 某一设备系列的自有协议：在设备端口上通过该协议连接，除非端口被更改或转发，否则为 34567。适用于自动检测找不到的录像机，或从本地网络之外访问的录像机。地址位于本地网络之外时，表单会以橙色显示警告：该协议不加密视频，而且许多设备对密码的保护很弱。该设备系列的名称见“连接方式”。
  • 列表中的品牌：通过 RTSP 直接连接，使用该品牌文档中公布的视频流路径。适用于设备上关闭了 ONVIF 的情况，或添加只提供 RTSP 的录像机。增加的部分有两个输入框：
    • 摄像头：1 到 64 之间的数字。填 1 时，设备作为单个摄像头添加；填 2 或更大的数字时，设备作为录像机添加，并占用录像机额度。网络扫描获知通道数量时会自动填入。
    • 路径输入框：留空时，Cam Hub 会依次尝试该品牌文档中公布的路径，并保留设备有响应的那一个。输入框中显示的是第一个尝试的路径。仅在需要指定某个路径时填写。

Cam Hub 内置了厂商协议的品牌不在列表中；如列表下方的说明所述，自动检测会找到这些设备。部分品牌需要先在厂商的 App 或网页界面中创建专用的摄像头账号或 ONVIF 账号，RTSP 才能使用；只用管理员账号可能被拒绝。部分品牌的路径因型号或固件而异，因此第一次尝试可能不匹配。表单会在路径输入框下方显示这些说明。品牌列表及各品牌的说明，参见“列表中的品牌”。

RTSP 和列表中的品牌只提供实时观看

这两种连接方式没有录像回放、PTZ 控制和快照。设备提供该品牌的第二路视频流时，SD 使用这一路；否则 SD 与 HD 显示同一路视频流。

未开启 HTTPS 时，设备控制使用 HTTP

设备控制（识别设备、读取通道列表、搜索录像）使用 http://address:port，为设备开启 HTTPS 后则使用 HTTPS；具有自有协议的设备系列改用该协议。只接受 HTTPS 的设备，可通过使用 HTTPS添加，参见“通过 HTTPS 添加设备”。

RTSP 和列表中的品牌的失败提示有所不同

设备无法连接或超时时，只显示出错了。请重试。使用这两种连接方式时，不支持的设备。表示所有候选路径都没有返回视频流。常见原因是 RTSP 端口有误，或设备上的视频流已关闭。

无法确定设备能否使用时，点击表单中的兼容性参考，查看支持和不支持的设备。表单从已指明设备品牌的扫描结果打开且地址未被更改时，不显示该入口，也不显示添加示例摄像头。

通过 HTTPS 添加设备

网页使用 HTTPS 的设备可以通过 HTTPS 添加，即使设备上的普通 HTTP 已关闭也可以。HTTPS 默认关闭，需要手动开启，并且只在选择自动检测和 ONVIF 时提供：某一设备系列的自有协议、RTSP 和列表中的品牌都没有可供 HTTPS 保护的网页界面。已添加的设备则在其设备页上切换到 HTTPS，参见“已保存设备的 HTTPS”。

  1. 在添加设备表单中输入地址、用户名和密码，然后点击高级。

    确认：该部分显示使用 HTTPS开关，处于关闭状态。

  2. 开启使用 HTTPS。

    确认：出现 HTTPS 端口输入框，其中为 443；该部分下方显示关于此选项的说明。

  3. 设备使用其他 HTTPS 端口时，在 HTTPS 端口中输入该端口。

    确认：输入框显示该端口。保持 443 时，Cam Hub 还会在 5001 和 8443 上查找；填写其他端口时，只使用该端口。

  4. 点击右上角的添加。

    确认：表单显示正在连接设备…。连接成功后，表单自动关闭，新设备出现在设备列表中。其设备页的信息卡片中显示 HTTPS 一行及端口。

  • 说明文字为仅适用于网页使用 HTTPS 的设备；如果不确定，请保持关闭。Cam Hub 会在此端口查找 HTTPS（保持 443 时，也会尝试 5001 和 8443），并信任设备当前出示的证书。之后可以在设备页面的“HTTPS”中查看。开关开启期间，即使折叠高级，该说明也会一直显示。
  • 查找 HTTPS 时不发送用户名和密码：Cam Hub 只检查哪些端口出示证书。没有任何端口出示证书时，表单显示这台设备刚才没有通过 HTTPS 响应。有多个端口出示证书时，会依次尝试，因此即使其中某个端口被转发到另一台设备，尝试也不会就此结束。
  • 出现此信息时，请先检查这些列表中列出的是通用检查项，参见“添加失败时：检查清单”。此外还请检查以下几项：
    • 在浏览器中用以 https:// 开头的地址打开设备的网页，确认设备是否使用 HTTPS 以及使用哪个端口。
    • 在 HTTPS 端口中输入该端口。保持 443 时，只检查 443、5001 和 8443。
    • 关闭使用 HTTPS，通过普通 HTTP 添加设备。
  • 选择 ONVIF 并开启使用 HTTPS时，Cam Hub 通过 HTTPS 在 HTTPS 端口上查找 ONVIF 服务，而不是在 HTTP 端口中的端口上。设备的 ONVIF 服务使用其他 HTTPS 端口时，请在 HTTPS 端口中输入该端口。
  • Cam Hub 信任的是添加时设备出示的证书。之后可以把它与设备自身网页上的证书进行核对，参见“已保存设备的 HTTPS”。
  • 开启使用 HTTPS时，自动检测只在找到的 HTTPS 端口上尝试内置的厂商协议和 ONVIF，不会尝试某一设备系列的自有协议和普通 RTSP，因此只提供 RTSP 的摄像头无法通过这种方式添加；请关闭使用 HTTPS后再添加。
  • HTTPS 加密的是对设备的控制。通过 RTSP 获取的视频不会因此加密。

添加失败时：检查清单

添加失败时，表单用红色显示错误信息。使用自动检测时，其下方列出找到的开放端口。再往下，表单列出请先检查这些。列表的顺序随失败类型而定，最可能的原因排在最前面。从上到下逐项检查，然后再次点击添加。

设备报告（实验性）

实验性功能，不保证支持

设备报告是实验性功能，可能随时更改或移除。发送报告并不意味着开发者会为该设备添加支持，也不保证回复、修复或时间表。有些设备在设计上就无法支持，例如因为协议封闭或私有、仅限云端运行、授权或加密限制，或硬件限制。此功能不是客户支持或紧急求助的渠道。

收集详细信息时，会用已输入的账号和密码登录设备。登录失败会被设备计数，也可能被设备记录。密码可能有误时，应先按“添加失败时：检查清单”的说明更正密码，而不要反复尝试。

带有实验性标记的将详细信息发送给开发者按钮，只在添加失败后出现在检查清单下方；添加成功时不显示。该功能仅在点击按钮后运行：它用只读请求检查设备，并生成一份文本报告供检阅。Cam Hub 绝不会自行上传报告；只有用户选择用自己的邮件账户通过电子邮件发送时，报告才会发出。

前提条件：已完成“添加失败时：检查清单”中的检查清单，且表单中的地址、用户名和密码就是设备实际使用的。

  1. 在添加失败的表单中，滚动到检查清单，点击其下方的将详细信息发送给开发者。

    确认：首次使用时，屏幕显示设备报告页面，其中有完整的须知收集详细信息之前。

  2. 阅读须知，然后点击我明白了——开始收集。

    确认：屏幕显示正在收集详细信息…以及各项检查的进度。

  3. 等待收集完成。

    确认：发现的情况用通俗的语言列出可能的原因和建议优先尝试的操作。没有明显问题时，屏幕显示没有发现明显的问题。

  4. 在包含的内容下，关闭不应发送的项目。

    确认：报告部分的文字立即更新。

  5. 检阅报告部分的全文。

    确认：报告为纯文本，始终使用英文。已自动遮蔽的数据由遮蔽标记替代。

  6. 点击通过电子邮件发送给开发者。

    确认：邮件撰写窗口打开，收件人为开发者。主题以 Cam Hub device report 开头，后接识别出的品牌和型号，未识别出时为 unknown device。邮件中包含下文所述的问题和报告，报告还会作为文件 cam-hub-report.txt 附加。

  7. 在问题下方填写回答。

    确认：回答显示在问题与报告上方的虚线之间。

  8. 检查邮件内容并发送。

    确认：邮件撰写窗口关闭，重新显示报告页面。

  9. 点击右上角的完成。

    确认：报告页面关闭，重新显示添加设备表单。

  • 确认过一次须知之后，报告页面顶部只显示简短的提醒；点击关于此功能可再次阅读完整须知。
  • 收集过程中，点击左上角的停止可提前结束。已发现的内容会保留，屏幕显示您已停止收集，因此此报告并不完整。尚未发送任何内容。并提供重新收集。
  • 包含的内容有五项：网络、HTTP 指纹、协议探测、RTSP 与视频和 App 运行记录，每项以一个字母标记。发现结果和报告头部始终包含在内。
  • 除通过电子邮件发送给开发者外，还可用复制复制报告，或用共享…转交。副本只保留在本设备上，约 2 分钟后失效。
  • 未设置邮件账户时，屏幕显示此设备尚未设置邮件：完整报告会复制到剪贴板，点击好会打开电子邮件 App，并带有报告的开头部分。需将完整报告粘贴到邮件中。
  • 报告只有在发送时才会离开本设备。除非您选择发送电子邮件，否则不会发送任何内容。报告中绝不包含您的密码。

登录行为

收集期间，需要登录的请求逐个发送，直到设备接受或拒绝凭据。设备拒绝凭据后，报告不再发送任何登录请求。导致生成报告的那次失败尝试本身就是登录被拒绝（用户名或密码错误。）时，报告根本不会尝试登录，以免账号被设备锁定。开启了使用 HTTPS时，报告会先在不登录的情况下查找设备的证书，再用该证书通过 HTTPS 重复尝试；设备没有出示证书时，报告不会登录。收集期间只发送只读请求，不会更改设备上的任何设置。

报告包含和不包含的内容

  • 包含：App 和系统的版本、手机的型号标识、语言设置、所选的连接方式（开启使用 HTTPS时包括 HTTPS 端口）、设备地址（私有网络地址的最后一段以 x 遮蔽；公网地址只给出其类别）、端口、失败尝试的错误代码、检测到的品牌和型号、开放的端口、设备响应的标头和结构（已遮蔽）、视频流的编码和参数、时钟和时区的差异，以及已执行的步骤及其结果。
  • 不包含：密码、用户名、为设备设置的名称、公网地址或动态域名、网络适配器的硬件地址、电子邮件地址、令牌及其他可识别身份的数据、图片和视频。较长的序列号只保留最后四个字符。
  • 遮蔽是自动进行的，每个被遮蔽的项目都会留下标记。发送前仍应检阅报告，任何项目都可以关闭。
邮件中的问题

邮件以一句英文开头，确认此功能为实验性功能，且发送报告并不保证获得支持。接着是您可以使用自己最熟悉的语言撰写，开发团队都能支持。和请尽量回答以下问题：，以及六个带编号的问题：设备标签上印刷的品牌和型号、固件版本、设备类型、预期与实际情况的差异、厂商自己的 App 或媒体播放器能否显示该设备，以及能在媒体播放器中打开的 RTSP 地址（须先删除其中的用户名、密码和地址）。其后是供填写回答的空白处和一条虚线，然后是报告。回答这些问题有助于开发者评估该设备。

已保存的报告

每份报告都保存在本设备上，保留最近的五份。添加失败后，将详细信息发送给开发者下方会出现一个带有保存日期的条目，例如上一份报告（2026年11月13日 上午9:41），点击即可打开最近保存的一份报告。已保存的报告按保存时的内容显示，不能逐项切换；要重新选择内容，须重新收集详细信息。

删除已保存的报告：

  1. 在报告页面底部，点击删除已保存的报告。

    确认：屏幕显示标题为要删除所有已保存的报告吗？的对话框，说明本设备上保存的所有设备报告都将被删除，已通过电子邮件发送的报告不受影响。

  2. 点击对话框中的删除已保存的报告。

    确认：所有已保存的报告均被删除。页面显示的是已保存的报告时，页面随即关闭；新收集的报告仍留在屏幕上，不会再次保存。

用网络扫描查找设备

位置：屏幕底部的工具标签页。

不知道设备的 IP 地址时，可在工具标签页中扫描一个网段。扫描会探测 80、554、2020、8000、34567 和 37777 这六个端口，并列出有响应的地址。随后，它通过许多摄像头和录像机无需登录即可响应的发现方式，询问找到的设备的身份。响应了该询问、但端口探测未找到的设备也会被加入列表。

  1. 点击屏幕底部的工具标签页。

    确认：在子网部分，本设备一行显示当前的网络地址和掩码，例如 192.168.1.10/24。地址输入框和范围已按当前网络填好。

  2. 可选：要扫描其他网络，在地址输入框中输入该网络，例如 192.168.1.0，并在范围菜单中选择范围。

    确认：输入框下方的一行显示将要扫描的网络和主机数量，例如将扫描 192.168.1.0/24 · 254 台主机。

  3. 点击扫描。

    确认：屏幕显示进度已扫描 254 台中的 120 台，按钮变为停止。

  4. 等待扫描结束；要提前结束，点击停止。

    确认：找到的设备列出有响应的地址，每个地址所在的行以标记显示其开放的端口。询问设备身份期间，显示正在识别设备…；之后，每个有设备响应的行会显示其名称或型号、品牌和型号、录像机的通道数量，尚待激活的设备还会显示未激活。没有发现任何设备时，屏幕显示尚未找到设备。

  5. 点击结果中的一行。

    确认：屏幕打开添加设备表单，地址已填入 IP 地址或主机名输入框，设备报告的自身信息也已带入；继续按“添加设备表单”中的步骤操作。

  • 除地址外，表单还会带入设备报告的信息：名称或型号作为名称，管理服务的端口作为 HTTP 端口，对于列表中的品牌，通道数量作为摄像头。对于端口不是默认值的自有协议设备系列，会选择该连接方式及其设备端口，并展开高级。
  • 扫描报告设备尚未激活时，表单开头会显示须先激活的提示，参见“激活新设备”。
  • 范围提供 /26、/25、/24、/23、/22 和 /16，各附网络掩码，例如 /24, 255.255.255.0；当前网络的前缀不在其中时，也会列出该前缀。范围内的地址超过 1024 个时，扫描会均匀抽样，而不是逐个探测，输入框下方的一行会显示例如将扫描 10.0.0.0/16 · 从 65534 台抽样 1024 台。
  • 地址输入框或范围与当前网络不同时，会出现使用我的子网，点击后恢复为当前网络。
  • 地址输入框的格式无效时，屏幕显示输入子网，例如 192.168.1 或 192.168.1.0。
  • 设备添加完成后，屏幕回到工具标签页，而不是设备列表。
扫描结果的局限

扫描只能发现在摄像头端口上有响应或响应发现请求的设备。不表明身份的设备可能是摄像头，也可能是录像机；类型在添加设备时才会确认。它开放的端口和服务器名称可作为判断厂商的线索。

扫描完整结束但没有任何结果时，屏幕显示如果摄像头就在这个网络里，请到隐私设置中确认已允许 Cam Hub 查找本地网络上的设备。本地网络权限被拒绝时，扫描不会报错，结果同样为空。请确认该权限已开启：设置 › 隐私与安全性 › 本地网络 › Cam Hub。
