16支持的品牌与连接方式

本章是唯一提到品牌名称的章节。它列出添加设备表单中的连接方式、每种方式能实现什么、设备必须提供什么，以及添加设备之前需要在设备上做哪些准备。本手册的其余部分只描述功能，不提品牌。

连接方式

添加设备表单中的高级 › 连接方式列表以四种方式开头：自动检测、ONVIF、Xiongmai (XMEye) 和 RTSP。其下的品牌部分按字母顺序列出 71 个品牌，并提供搜索框；品牌也可以通过其摄像头销售时使用的其他名称搜到。Hikvision、Dahua 和 Synology 不在列表中：自动检测会用它们各自的协议找到这些设备。表单本身参见“添加设备表单”，如何选择参见“选择连接方式”。

选项Cam Hub 的做法适用对象账号
自动检测（默认） 先在不登录的情况下检查该地址上哪些端口是开放的。然后按以下顺序尝试：在主网页端口上，先尝试在该端口识别出的品牌，再依次尝试 Hikvision 的协议、Dahua 的协议和 Synology Surveillance Station 的编程接口；在其他端口上识别出这三者之一的情况，例如 Synology NAS 的网页端口 5000；Xiongmai 的自有协议，使用端口 34567，仅限本地地址；在每个有响应的端口上尝试 ONVIF；最后在每个有响应的 RTSP 端口上尝试普通 RTSP，先用设备透露的品牌的路径，再用大多数摄像头使用的路径，最后用列表中每个品牌的路径。第一种连接成功的方式会被保留，连同其端口。Hikvision、Dahua、Synology 或 Xiongmai 拒绝登录时，尝试立即结束；ONVIF 和 RTSP 在第二次被拒绝后才结束。在“高级”下输入的端口会被优先尝试；输入的端口不是 80 或 554 且处于开放状态时，只使用该端口。 大多数设备：Hikvision、Dahua 和 Synology 的摄像头与录像机，本地网络中的 Xiongmai 设备，任何带 ONVIF 的设备，以及在常用路径或列表中某个品牌的路径上提供 RTSP 的摄像头。 设备的账号。Synology：网络存储设备上获准使用 Surveillance Station 的账号。
ONVIF 跳过检测，只在 HTTP 端口中的端口上使用开放的 ONVIF 协议。Cam Hub 在 /onvif/device_service 查找该服务，该地址无响应时，再查找 /onvif/service 和 /onvif/device。视频从设备公布的地址获取。 任何带 ONVIF 的摄像头或录像机；也适用于要通过 ONVIF 使用的 Hikvision、Dahua 或 Synology 设备。 设备的 ONVIF 用户。设备单独保存 ONVIF 用户列表时，该列表中必须有一个用户。
Xiongmai (XMEye) 在设备端口中的端口上使用 Xiongmai 的自有协议（XMEye / NetSurveillance），除非端口被更改或转发，否则为 34567。接受任何地址，包括本地网络之外的地址；对于这样的地址，表单会警告：该协议不加密视频，而且许多设备对密码的保护很弱。 自动检测找不到、使用其他端口，或从本地网络之外访问的 Xiongmai 摄像头和录像机。 设备的账号。
RTSP 通过普通 RTSP 连接，尝试大多数摄像头使用的路径或输入的路径。不联系设备的任何控制接口。仅限实时观看。 关闭了 ONVIF、且品牌不在列表中的任何品牌的摄像头。 设备的摄像头账号。
列表中的品牌（参见“列表中的品牌”） 通过普通 RTSP，使用厂商文档中公布的视频流路径连接。不联系设备的任何控制接口。仅限实时观看。 该品牌的设备在 ONVIF 关闭或不可用时，以及该品牌只提供 RTSP 的录像机。 设备的摄像头账号；其中五个品牌需要单独的账号。

自动检测是起点。自动检测报告不支持的设备。时，或有意要通过 ONVIF 使用设备时，下一个选择是 ONVIF。自动检测无法连接的 Xiongmai 设备，应选择 Xiongmai (XMEye)。列表中的品牌或 RTSP 是最后的选择，用于关闭了 ONVIF 的设备。报告其视频已加密的 Xiongmai 录像机无法通过 Xiongmai 的自有协议观看；此时自动检测会转而尝试 ONVIF，这样的录像机应使用 ONVIF 添加。开发者测试过选定的 Hikvision、Dahua 和 Synology 设备。某个具体型号能否使用（无论哪种方式），取决于其固件、设置、视频流格式、账号权限和网络。

  • 实时观看：使用 ONVIF 时，设备必须公布视频流地址；设备没有指明其媒体服务时，Cam Hub 会在该服务的常用地址上询问。视频通过 TCP 上的 RTSP 获取，设备拒绝 TCP 时改用 UDP。
  • SD 和 HD：使用 Synology Surveillance Station 时，该选项隐藏；SD 使用摄像头的低分辨率视频流（如果有）。使用 Xiongmai 时，HD 是主码流，SD 是辅码流。使用 ONVIF 时，设备最大的配置文件为 HD，最小的为 SD，只有一个配置文件时二者共用。使用 RTSP 和列表中的品牌时，设备提供与所找到路径对应的第二路视频流时，SD 使用这一路；否则 SD 与 HD 显示同一路视频流。
  • 录像回放：使用 Hikvision 时，带自身存储的摄像头与录像机一样回放。使用 Dahua 时，播放录像机的主码流，跳到另一时间会从该时刻重新开始回放。使用 Synology Surveillance Station 和 Xiongmai 时，录像从所选时刻开始以流的方式传输。使用 ONVIF 时，设备需要 ONVIF 为回放定义的搜索和重放服务。
  • 回放速度：使用 Hikvision、Dahua 和 ONVIF 时，录像机可能拒绝更快的速度，此时 Cam Hub 会显示提示。使用 Synology Surveillance Station 和 Xiongmai 时，流式回放没有速度按钮。
  • 日历：报告哪些日期有录像的 Hikvision 录像机，会在回放日期的日历中标出这些日期，参见“录像日历”。
  • 人员搜索：录像机需要有检测到人员的索引。
  • PTZ：使用 Hikvision 时，通道需要开启 PTZ；设备列出预置位时才会显示这些预置位，原点位置始终可用。使用 Dahua 时，PTZ 必须绑定到该通道；提供预置位，但没有原点位置。使用 Synology Surveillance Station 时，控件取决于系统为该摄像头报告的内容：四个方向，以及（如果报告）原点位置。使用 Xiongmai 时，带云台的摄像头提供方向、变焦以及按编号 1 到 16 调用的预置位，没有原点位置。使用 ONVIF 时，各个轴取决于设备报告的内容；只有变焦的摄像头没有方向控制盘。参见“PTZ 控制：移动摄像头”。
  • 定位：Hikvision 摄像头报告支持按画面中的点或区域定位时提供。
  • 快照：使用 Xiongmai 时，图片取自实时视频流的第一个完整帧。使用 ONVIF 时，设备必须提供快照地址。
  • 录制片段：适用于视图播放的 H.264 和 H.265 画面，参见“录制片段”。使用 Synology Surveillance Station 时，没有获取视频流权限的账号只会收到单张图片（MJPEG），其视图没有录制按钮。Synology Surveillance Station 以文件形式提供的录像会整个共享。
  • 声音：使用 Synology Surveillance Station 时，通过其常用的流传输路径只能播放 G.711。Xiongmai 设备发送 G.711。
  • 对讲：提供给报告具备 G.711 双向音频通道的单独 Hikvision 摄像头；录像机的通道不提供。参见“双向对讲”。
  • 磁盘健康：Hikvision 报告每块磁盘的状态，设备提供时还有 S.M.A.R.T. 详细信息。Dahua 报告状态、容量以及（如果有）温度，但没有 S.M.A.R.T. 详细信息。Synology NAS 通过 SNMP 读取，须在 NAS 上开启 SNMP 并在 Cam Hub 中设置。参见“磁盘健康”。
  • 通道列表：Hikvision 和 Dahua 列出录像机的通道及其名称和信号状态，不是录像机的设备只有一个通道。Synology Surveillance Station 把系统中的每个摄像头列为一个通道，并带信号状态。Xiongmai 设备报告其通道数量和为通道设置的名称，不带信号状态。ONVIF 为每个独立的视频源列出一个通道，不报告信号状态。RTSP 和列表中的品牌没有列表：需要输入摄像头数量（1 到 64），每个通道都显示为在线。
  • HTTPS：设备的网页界面提供 HTTPS 时可用，需要为每台设备单独开启，参见“通过 HTTPS 添加设备”和“已保存设备的 HTTPS”。Xiongmai 的自有协议和普通 RTSP 没有可供 HTTPS 保护的网页界面。通过 RTSP 传输的视频不会因 HTTPS 而加密。

无论哪种方式都不提供：对焦和光圈控制、保存或导出录像，以及登录云账号。

列表中的品牌

品牌部分中的品牌通过普通 RTSP 连接。选择品牌会增加一个以该品牌命名的部分，其中有摄像头输入框（1 到 64）和一个路径输入框。填 1 时，设备作为以该品牌命名的摄像头添加；填更大的数字时，作为带通道 CH1 到 CHn 的录像机添加，并按录像机计入套餐。路径输入框留空时，Cam Hub 会依次尝试文档中公布的路径，并保留设备有响应的那一个。只有需要指定某个路径时才需要输入。选择 RTSP 时同样如此，使用的是大多数摄像头使用的路径。

这 71 个品牌为：2N、3S Vision / A-Linking、ACTi、Acumen、AirLive、ANNKE、Apexis / Sumpple、Arecont Vision、Avigilon、AVTECH、Axis、Basler、Beward、Bosch Security、Brickcom、Canon、COMPRO、D-Link、DIGITUS、DynaColor、EDIMAX、eneo、EnGenius、Etrovision、eufy、EverFocus、EZVIZ、FlexWATCH、Foscam、GeoVision、Grandstream、Hanwha Vision (Wisenet)、HVIEW、i-PRO (Panasonic)、IDIS、Imou、INSTAR、iPUX、IQinVision (IQeye)、Jovision、JVC、LILIN、Lorex、Messoa、Milesight、MOBOTIX、NEXCOM、Night Owl、Oncam、Pelco、PiXORD、Reolink、SHANY、Siemens、Sony、Sricam、StarDot、Sunell、Swann、TP-Link (Tapo / VIGI)、TRENDnet、TVT、UniFi (Ubiquiti)、Uniview (UNV)、VIVOTEK、Vstarcam、Wansview、Wyze、Y-cam、YI / Kami、Zavio。

  • 单独的账号：Axis、TP-Link (Tapo / VIGI)、ANNKE、MOBOTIX 和 2N 需要先在厂商的网页界面或 App 中创建自己的摄像头账号或 ONVIF 账号，RTSP 才能使用。只用管理员登录可能被拒绝。
  • RTSP 端口：三个品牌使用其他默认端口，选择品牌时表单会自动填入：ACTi 为 7070，Foscam 为 88，Vstarcam 为 10554。
  • 录像机：以下品牌有文档公布的录像机形态：3S Vision / A-Linking、ANNKE、AVTECH、Beward、DIGITUS、eneo、eufy、GeoVision、Hanwha Vision (Wisenet)、IDIS、Imou、Lorex、Milesight、Night Owl、Pelco（编码器）、Reolink、Sunell、Swann、TP-Link (Tapo / VIGI)（VIGI 录像机）、TRENDnet、TVT、Uniview (UNV) 和 VIVOTEK。其他品牌的每个通道都使用摄像头路径；只有包含通道编号的路径，才会在每个通道上连到不同的摄像头。
  • 因设备而异的路径：许多品牌的部分路径取决于型号或固件，因此第一次尝试可能不匹配。对这些品牌，表单会在路径输入框下方显示说明。
  • 自动检测使用相同的路径：其他方式都无法连接时，自动检测会自行尝试列表中每个品牌的路径，并把摄像头作为单个摄像头添加。手动选择品牌主要用于录像机（以便输入摄像头数量），或用于固定某一个路径。

仅限实时观看

通过 RTSP 或这些品牌连接时，没有录像回放、PTZ 控制、快照和通道列表。各项功能列于“各方式支持哪些功能”。

要求与限制

主题要求或限制
HTTP 和 HTTPSCam Hub 通过普通 HTTP 联系设备，为设备开启 HTTPS 后则通过 HTTPS；Xiongmai 设备则改用其自有协议。视频通过 RTSP 获取，先用 TCP，设备拒绝 TCP 时改用 UDP；HTTPS 不会加密视频。使用 HTTPS 时，Cam Hub 信任开启 HTTPS 时设备出示的证书（包括自签名证书），或公共证书颁发机构为该地址签发的证书。关闭了 HTTP 的设备，或只接受 HTTPS 的设备，通过使用 HTTPS添加，参见“通过 HTTPS 添加设备”。对网络存储设备，在 HTTP 端口中输入其 HTTP 网页界面的端口，例如 5000；开启使用 HTTPS后，Cam Hub 也会自行找到其 HTTPS 端口 5001。
开启 ONVIF选择 ONVIF 时，设备上必须开启 ONVIF。Cam Hub 在 HTTP 端口中所填端口的 /onvif/device_service、/onvif/service 或 /onvif/device 查找该服务。有些设备在出厂设置中关闭了 ONVIF。
开启 RTSP视频通过 RTSP 获取。使用自动检测时，Cam Hub 会自行找到 RTSP 端口；否则使用 RTSP 端口中所填的端口（通常为 554）。网络存储设备可能优先使用自己的流传输路径。设备有 RTSP 认证设置时，应选择 Digest 方式。
单独的 ONVIF 用户有些设备保存的 ONVIF 用户列表与网页界面的用户相互独立，管理员登录对 ONVIF 无效。请在该列表中创建一个用户。列表中有五个品牌在 RTSP 可用之前需要自己的摄像头账号或 ONVIF 账号：Axis、TP-Link (Tapo / VIGI)、ANNKE、MOBOTIX 和 2N。
账号权限账号需要有观看实时视频的权限，回放则需要读取录像的权限。对 Synology，账号必须获准使用 Surveillance Station。Cam Hub 没有验证码输入框，因此要求两步验证的账号无法使用。
设备时钟ONVIF 登录带有设备的时间戳。时钟相差几分钟就会导致登录失败。请在设备上设置时间，例如使用网络校时。录像的时间是录像机的时钟时间。
同一网络，无云端Cam Hub 直接连接设备的地址，没有云端中继。在家庭网络之外，只能通过能从外部到达的地址连接设备。只能通过厂商云端 App 使用的设备无法添加，Cam Hub 也不提供云账号登录。
本地网络之外的 Xiongmai 设备自动检测只对本地地址使用 Xiongmai 的自有协议。位于端口转发或动态域名之后的 Xiongmai 设备，应使用 Xiongmai (XMEye) 添加。该协议不加密视频，而且许多设备对密码的保护很弱。
视频格式Cam Hub 播放 H.264 和 H.265，由手机硬件解码。不支持 H.265 硬件解码的手机，以及画面尺寸超出解码器上限的情况，都不会显示画面。MJPEG 仅作为其中一个系列实时观看的备选。
声音收听时播放 G.711（A-law 和 µ-law）和 AAC-LC；其他任何格式都没有声音。通过摄像头说话仅适用于提供 G.711 双向音频的单独 Hikvision 摄像头。
被锁定的账号多次输错后，设备可能把账号锁定，通常约 30 分钟。自动检测的端口检查不发送登录请求。品牌自有协议第一次拒绝登录时，Cam Hub 就会停止；通过 ONVIF 或 RTSP 时，在第二次被拒绝后停止。设备报告在被拒绝之后也不再发送登录请求。
重新添加设备相同的地址、端口和用户名会更新已保存的设备，而不是创建第二个。

摄像头与录像机

设备列表中的标记为摄像头或录像机。录像机占用套餐录像机额度中的一个名额，参见“哪些内容占用额度”。Cam Hub 按以下方式判定。

方式设备被视为录像机的条件
Hikvision设备报告的设备类型包含 NVR 或 DVR
Dahua型号名称包含 NVR、DVR 或 XVR；否则设备是一个摄像头
Synology Surveillance Station始终如此；系统中的每个摄像头是一个通道
Xiongmai (XMEye)设备报告的通道多于一个，或其设备类型包含 DVR 或 NVR
ONVIF设备有多个独立的视频源；因此带多个传感器的摄像头也可能被视为录像机
自动检测找到的 RTSP从不；设备作为一个摄像头添加
手动选择的 RTSP 和列表中的品牌摄像头输入框中的数字大于 1

在设备上需要做哪些准备

以下检查清单适用于所有品牌。设备没有的项目可以跳过。

  • 激活设备并设置管理员密码。全新的设备必须先激活，任何 App 才能登录，参见“激活新设备”。
  • 在家庭网络中为设备设置固定地址，可在设备中设置，也可在路由器中预留。Cam Hub 会保留输入的地址，参见“设备已添加，但无法连接”。
  • 让手机和设备处于同一网络，两者之间没有访客网络、独立的 VLAN、客户端隔离或 VPN。
  • 开启设备的 HTTP 服务并记下其端口，通常为 80。
  • 开启 RTSP 并记下其端口，通常为 554。设备提供 RTSP 认证选项时，选择 Digest。
  • 设备有相关设置时，开启 ONVIF；设备保存自己的用户列表，或品牌有此要求时，创建单独的 ONVIF 或摄像头用户。
  • 设置日期、时间和时区，例如使用网络校时。
  • 把视频设为 H.264 或 H.265，分辨率适中，关键帧间隔为一到两秒。设备提供时，使用分辨率较低的子码流作为 SD。
  • 使用可以观看实时视频、回放时可以读取录像的账号，对象为要显示的通道。
  • 要使用回放，请确认设备在录像，且装有硬盘或存储卡。
  • 要查看 Synology NAS 的磁盘健康，请在 NAS 上开启 SNMP。
  • 记下添加设备表单要求填写的地址、用户名和密码，以及端口，以备自动检测找不到设备时使用。
无法添加的设备

只能通过厂商云端 App 使用或不提供本地网络连接的设备，无法添加到 Cam Hub。只接受 HTTPS 的设备通过使用 HTTPS添加，参见“通过 HTTPS 添加设备”。

激活新设备

部分品牌（其中包括 Hikvision）的新设备或已重置的设备尚无管理员密码。必须先激活，任何 App 才能登录：激活即设置管理员密码。在此之前，所有登录都会被拒绝，添加设备会失败并显示用户名或密码错误。

网络扫描可以显示 Hikvision 设备尚未激活：

  • 设备响应扫描的询问并报告尚未激活时，它在找到的设备中的那一行显示未激活，参见“用网络扫描查找设备”。
  • 从该行打开的添加设备表单开头显示提示这台 Hikvision 设备尚未激活。请先用 Hikvision 的 SADP 工具或设备自带的网页设置管理员密码来激活它。
  • 不响应扫描询问的设备，无论是否已激活，都不显示这样的标记。

激活设备：

  1. 按设备文档的说明，用厂商自己的工具或在设备自带的网页上激活设备，并在其中设置管理员密码。

    确认：设备接受用管理员账号和新密码登录，例如在其网页上。

  2. 在 Cam Hub 的添加设备表单中，输入管理员账号（通常为 admin）和新密码，然后点击添加。

    确认：表单关闭，设备出现在设备列表中。

如果仍然添加失败，参见“添加失败时：检查清单”。

App 中的兼容性参考

路径：设备 › ＋ › 添加设备 › 兼容性参考。兼容性页面列出开发者声明支持和不支持的内容。

  • 支持：Hikvision 和 Dahua（都标有推荐），然后是 Synology、Xiongmai (XMEye)、带有说明局域网（LAN）连接的 SoCatch (iWatch)、大多数 RTSP 摄像头和大多数 ONVIF 摄像头。
  • 不支持：SoCatch (iWatch) 的广域网连接，因为它通过其厂商的远程访问服务运行，而该服务不向其他 App 开放。这类摄像头应在本地网络中添加。
  • Hikvision 条目有如何让它不连接互联网按钮，其中的说明涉及让摄像头不设置网关、阻止其访问互联网，以及这样一来只能在摄像头所在的网络中观看。在某些地区，该按钮不会显示。
  • 底部的说明声明：这些名称是其所有者的商标，Cam Hub 由开发者独立开发，连接成功只表示技术上兼容。
